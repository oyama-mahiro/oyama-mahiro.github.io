# 阶段3-10 在线更新、尺度估计、置信度保护与遮挡恢复

阶段3-8建立了相关滤波的训练和检测闭环，阶段3-9把输入特征扩展为HOG、FHOG和CSRT可靠性特征。到这一步，一个固定尺寸、固定模型的FHOG跟踪器已经可以在相邻帧中寻找目标，但真实视频又带来两个连续变化：目标外观会变化，目标在画面中的尺寸也会变化。

更新模型能够适应人物转身、蹲下和车辆视角变化；错误位置上的更新也会把树枝、道路或其他背景写进模型。尺度搜索能够让框跟随目标远近；过于敏感的尺度判断又会让框宽高不断抖动。本章围绕这两个矛盾，使用Demo14、Demo15和Demo16逐层加入在线更新、尺度估计、置信度门控、健康模板和局部重捕获。

整体因果链为：

```text
固定模型无法适应外观变化
→ 加入在线模型更新
→ 错误位置也可能被更新，产生模板污染
→ 用Peak和PSR分别控制位置、尺度、模型和健康模板
→ 目标远近变化仍需额外尺度搜索
→ 内部框合法化，外部显示框独立平滑
→ 遮挡时冻结高风险操作并保留健康模板
→ 连续弱响应或丢失后执行局部重捕获
```

## 1 固定模型跟踪遇到的外观与尺度变化问题

### 1.1 固定FHOG模型为什么会逐渐失效

Demo13初始化时从第一帧目标区域提取 $24\times24\times31$ 的FHOG模板，并训练模型系数。后续每一帧都用同一份模板寻找目标，模型本身保持不变。

如果目标只发生小范围平移，固定模型通常能够保持清晰响应。真实目标还会发生以下变化：

- 人物转身、摆臂、蹲下，轮廓方向分布改变；
- 车辆从正面变成侧面，车窗、车灯和车身边缘的位置改变；
- 光照、阴影和相机曝光变化，使灰度及颜色结构改变；
- 目标靠近或远离相机，原图中的宽高改变。

FHOG对光照和小幅形变具有一定稳定性，但它保存的仍是初始化时的目标外观。当前外观与历史模板之间的差距不断增大后，响应峰值会降低，旁瓣会增多，最终可能由背景产生更高响应。

尺度变化还会造成几何错位。固定跟踪框太小时只覆盖目标的一部分；跟踪框太大时会吸收更多背景。位置相关只能回答“目标中心向哪里移动”，还需要额外判断“目标框应该多大”。

### 1.2 外观适应与模板污染之间的矛盾

在线更新的基本想法是：当前帧定位成功后，在新目标位置重新提取FHOG并训练一份当前模型，再让历史模型少量吸收当前模型。这样，模型可以逐步跟随外观变化。

问题出现在定位错误时。假设人物经过树木，相关滤波响应暂时落在树干上。如果程序仍把树干位置作为训练区域，新模型中就会包含大量树木特征。连续多帧更新后：

```text
人物模型
→ 人物与树枝的混合模型
→ 树枝占主要部分的模型
→ 即使人物重新出现，树木仍产生更高响应
```

这就是模板污染。它解释了“最初完全框住人物，人物经过树后模板最终变成树”的现象：污染发生在正常FHOG在线更新阶段，局部重捕获可能尚未启动。

因此，在线跟踪不能只包含“检测成功后更新”这一条规则，还要把本帧结果拆成四种风险不同的权限：

```text
本帧位置是否接受
本帧尺度是否允许变化
本帧FHOG模型是否允许更新
本帧健康模板是否允许刷新
```

## 2 Demo14的相关滤波模型在线更新

### 2.1 为什么需要在新目标位置重新提取训练特征

每帧检测开始时，跟踪器只知道上一帧目标框。它以旧框为中心截取搜索区域，提取检测FHOG并计算响应图。目标在当前帧中已经移动，所以检测特征中的目标通常偏离搜索区域中心。

相关滤波训练标签默认把目标放在特征图中心。如果直接拿检测特征训练，程序等价于告诉模型“偏离中心的目标就是中心正确样本”，会把位移误差写进模型。正确顺序是：

```text
以上一帧框为中心提取检测特征
→ 计算响应图和位移
→ 将目标框移动到当前帧新位置
→ 以新目标框为中心重新提取训练特征
→ 训练当前帧模型
```

以下代码来自Demo14的 `OnlineFhogTracker::update()` 第784—898行核心部分。检测特征和训练特征来自同一帧，但中心位置不同。

```cpp
// detectionFeature以旧targetRect_为中心，用于回答目标本帧移动了多少。
const cc_fhog_demo::CcFhogResult detectionFeature =
    featureExtractor_.extractFromFrame(frame, targetRect_);

// 使用历史相关滤波模型检测当前FHOG，输出响应图、Peak、PSR和Cell位移。
const response_detection_demo::DetectionResult detection =
    response_detection_demo::detectTarget(
        model_,
        detectionFeature.feature,
        config_.trackerConfig.psrExclusionRadius);

// featureDisplacement使用特征Cell单位；函数结合Cell大小和搜索图缩放比例换回原图像素。
const int cellSize = config_.trackerConfig.featureGeometry.cellSize;
result.imageDisplacement =
    response_detection_demo::featureDisplacementToImage(
        detection.peak.featureDisplacement,
        cv::Size(cellSize, cellSize),
        detectionFeature.searchPatch);

// Demo14只更新中心位置，宽高继续沿用历史目标框。
cv::Rect2f candidateRect(
    targetRect_.x + result.imageDisplacement.x,
    targetRect_.y + result.imageDisplacement.y,
    targetRect_.width,
    targetRect_.height);

// 候选框可能越过画面边缘；该函数通过移动框的位置保留原有宽高。
targetRect_ = clampPositionToFrame(candidateRect, frameSize_);

// Demo14用Peak做最小更新保护；默认阈值来自配置中的0.35。
result.updateAllowed =
    !config_.enableLowConfidenceProtection ||
    result.peakValue >= config_.updatePeakThreshold;

// 只有置信度通过且学习率大于0时，当前帧外观才允许进入历史模型。
if (result.updateAllowed && config_.learningRate > 0.0F) {
    // 目标框已经移动到本帧位置，所以重新提取的目标位于训练搜索区域中心。
    const cc_fhog_demo::CcFhogResult trainingFeature =
        featureExtractor_.extractFromFrame(frame, targetRect_);

    // 使用本帧居中的FHOG训练临时模型；历史model_此时还没有改变。
    const filter_train_demo::CorrelationFilterModel currentModel =
        filter_train_demo::trainCorrelationFilter(
            trainingFeature.feature,
            config_.trackerConfig.labelSigma,
            config_.trackerConfig.kernelSigma,
            config_.trackerConfig.regularization);

    // 使用相同学习率同时融合templateFeature和alphaSpectrum。
    interpolateTrackingModel(model_, currentModel, config_.learningRate);

    // 该标志表示本帧确实改变了历史模型，供上层显示和调试。
    result.modelUpdated = true;
}
```

### 2.2 模板特征和模型系数的同步更新

高斯核KCF模型包含两项需要跨帧保存的状态：

- `templateFeature`：历史目标的FHOG模板特征；
- `alphaSpectrum`：由模板与高斯标签训练得到的频域模型系数。

检测时先用历史模板与当前特征计算高斯核相似度图，再用Alpha得到最终响应。因此两项必须属于同一更新进度。如果只更新模板，Alpha仍然对应旧模板；如果只更新Alpha，核相似度仍以旧外观为参考。

二者使用相同学习率 $\eta$：

$$
X_t=(1-\eta)X_{t-1}+\eta X_{current}
$$

$$
\hat{\alpha}_t=(1-\eta)\hat{\alpha}_{t-1}+\eta\hat{\alpha}_{current}
$$

以下代码来自Demo14的 `interpolateTrackingModel()` 第493—586行。它先检查模型兼容性，再处理学习率的两个边界，最后调用OpenCV `addWeighted()` 完成矩阵插值。

```cpp
/**
 * @brief 按学习率同时融合历史模板特征和Alpha频谱。
 * @param historicalModel 输入输出参数；调用前保存旧模型，调用后保存融合结果。
 * @param currentModel 当前可靠目标位置重新训练的临时模型，函数不会修改它。
 * @param learningRate 当前模型所占权重，范围为[0,1]。
 */
void interpolateTrackingModel(
    filter_train_demo::CorrelationFilterModel& historicalModel,
    const filter_train_demo::CorrelationFilterModel& currentModel,
    float learningRate)
{
    // 拒绝NaN、无穷值和范围外学习率，防止非法权重污染整张模型。
    if (!std::isfinite(learningRate) ||
        learningRate < 0.0F || learningRate > 1.0F) {
        throw std::invalid_argument(
            "interpolateTrackingModel: learningRate must be in [0, 1].");
    }

    // 两代模型必须拥有相同尺寸、类型和通道，才能执行逐元素加权。
    if (!matricesAreCompatible(
            historicalModel.templateFeature,
            currentModel.templateFeature) ||
        !matricesAreCompatible(
            historicalModel.alphaSpectrum,
            currentModel.alphaSpectrum)) {
        throw std::invalid_argument(
            "interpolateTrackingModel: model matrices are incompatible.");
    }

    if (learningRate == 0.0F) {
        return; // 当前模型权重为0，历史模板和Alpha保持不变。
    }

    if (learningRate == 1.0F) {
        // 完全采用当前模型；clone()让历史模型拥有独立矩阵数据。
        historicalModel.templateFeature = currentModel.templateFeature.clone();
        historicalModel.alphaSpectrum = currentModel.alphaSpectrum.clone();
        return;
    }

    // 两个权重之和固定为1，保证融合结果处于旧模型和当前模型之间。
    const double historicalWeight = 1.0 - static_cast<double>(learningRate);
    const double currentWeight = static_cast<double>(learningRate);

    // 先写入临时矩阵；两项都计算完成后再一起提交，避免模型处于半更新状态。
    cv::Mat blendedTemplate;
    cv::Mat blendedAlpha;

    // 对H×W×C模板特征逐元素插值，使目标外观缓慢吸收当前可靠样本。
    cv::addWeighted(
        historicalModel.templateFeature, historicalWeight,
        currentModel.templateFeature, currentWeight,
        0.0, blendedTemplate);

    // alphaSpectrum是CV_32FC2复数矩阵，addWeighted会对实部和虚部分别执行同样插值。
    cv::addWeighted(
        historicalModel.alphaSpectrum, historicalWeight,
        currentModel.alphaSpectrum, currentWeight,
        0.0, blendedAlpha);

    // 把两项临时结果同时写回历史模型，后续检测将使用同一时间版本的数据。
    historicalModel.templateFeature = std::move(blendedTemplate);
    historicalModel.alphaSpectrum = std::move(blendedAlpha);
}
```

### 2.3 学习率过大、过小和完全不更新的区别

学习率决定当前样本一次进入历史模型的比例。

| 学习率 | 模型行为 | 主要风险 |
|---:|---|---|
| $0$ | 历史模型完全不变，等价于Demo13固定模型 | 无法适应长期外观变化 |
| $0.005$ | 每次只吸收0.5%的当前模型 | 适应较慢，抗短时污染较强 |
| $0.02$ | Demo14和CC常规更新的参考值 | 外观适应与稳定性的折中 |
| $0.20$ | 每次吸收20%的当前模型 | 适应快，错误样本也会迅速污染模型 |
| $1$ | 当前模型完全覆盖历史模型 | 单帧误跟即可改写全部模型 |

学习率控制一次更新有多重，更新间隔控制多久更新一次。两者需要分别理解。即使 $\eta=0.005$ 很小，如果遮挡期间连续更新几十帧，背景仍会逐渐累积进模型。

### 2.4 每N个连续可靠帧更新一次

“每5个视频帧更新一次”只检查帧号。第1—4帧可能全部处于遮挡，第5帧仍会机械触发更新。Demo16采用“每5个连续允许更新的可靠帧更新一次”：

```text
可靠帧 → 计数加1
可靠帧 → 计数加1
Weak/Lost → 计数清零
重新连续累计到5 → 执行一次更新并清零
```

以下代码来自Demo16第1977—2024行。当前配置为 `modelUpdateInterval=5`、`learningRate=0.005`。

```cpp
// 三个条件分别控制功能开关、置信度许可和学习率；任一个失败都保持旧模型。
if (config_.enableOnlineUpdate &&
    result.confidence.modelUpdateAllowed &&
    config_.learningRate > 0.0F) {
    ++modelUpdateEligibleFrameCount_; // 只累计门控允许更新的连续可靠帧。

    // modelUpdateInterval表示需要累计多少个连续可靠帧，不是普通视频帧号间隔。
    const bool intervalReached =
        modelUpdateEligibleFrameCount_ >= config_.modelUpdateInterval;

    if (intervalReached) {
        // 检测特征以旧框为中心；训练前仍需在已接受的新位置重新提取FHOG。
        const cc_fhog_demo::CcFhogResult trainingFeature =
            featureExtractor_.extractFromFrame(frame, targetRect_);

        // 使用当前居中特征重新训练一份完整临时模型，历史model_仍保持原值。
        const filter_train_demo::CorrelationFilterModel currentModel =
            filter_train_demo::trainCorrelationFilter(
                trainingFeature.feature,
                trackerConfig.labelSigma,
                trackerConfig.kernelSigma,
                trackerConfig.regularization);

        // 小学习率插值让历史模型逐步适应外观，避免被单帧样本完全覆盖。
        online_update_demo::interpolateTrackingModel(
            model_, currentModel, config_.learningRate);

        // 向调用者报告本帧已经真正执行训练和插值。
        result.modelUpdated = true;
        modelUpdateEligibleFrameCount_ = 0; // 本轮更新完成，下一轮重新累计。
    }
}
```

当 `modelUpdateAllowed=false` 时，Demo16会在后续分支清零 `modelUpdateEligibleFrameCount_`。这保证计数表达连续可靠帧数，不能跨过遮挡帧继续累计。

## 3 响应峰值、PSR与置信度决策

### 3.1 响应峰值能够说明什么

Peak是响应图中的最大数值。它表示当前模型在所有候选位移中找到的最高响应，Peak位置用于计算目标位移，Peak大小可以反映最佳候选与模型的匹配强度。

Peak较高仍可能对应错误目标。树干具有稳定竖直边缘，相似车辆具有接近的轮廓，重复窗户也可能产生较高响应。Peak只看最大值本身，没有观察其他候选位置是否也同样高。

因此，Demo16让Peak主要决定位置处于正常、较弱还是严重丢失区间，再用PSR补充主峰突出程度。

### 3.2 PSR怎样判断主峰是否突出

峰值旁瓣比（Peak-to-Sidelobe Ratio，PSR）比较主峰和其余响应分布。程序先排除主峰附近的一小块区域，把剩余响应称为旁瓣，再计算：

$$
PSR=\frac{r_{peak}-\mu_{side}}{\sigma_{side}+\varepsilon}
$$

$r_{peak}$ 是主峰，$\mu_{side}$ 是旁瓣均值，$\sigma_{side}$ 是旁瓣标准差。两个响应图都可能具有 $0.8$ 的Peak：

- 其他位置大多在 $0.1$ 附近时，主峰非常突出，PSR较高；
- 其他位置大量分布在 $0.7$ 附近时，主峰缺少唯一性，PSR较低。

PSR也有边界。目标外观变化可能让整张响应图整体降低，但仍保留一个相对突出的主峰；重复纹理也可能偶然产生尖锐错误峰。它适合与Peak、连续帧计数、运动和尺度约束共同使用。

### 3.3 Peak与PSR分别控制哪些操作

Demo16没有把置信度压缩成一个 `success`。当前代码把Peak和PSR映射为四种许可：

| 许可 | 作用 | 风险 |
|---|---|---|
| `positionAllowed` | 是否把候选位置写入内部目标框 | 错误位置会让下一帧搜索中心漂移 |
| `scaleSearchAllowed` | 是否测试放大或缩小尺度 | 弱响应下容易造成框宽高突变 |
| `modelUpdateAllowed` | 是否让当前FHOG进入历史模型 | 错误更新会形成模板污染 |
| `healthyTemplateRefreshAllowed` | 是否覆盖重捕获使用的健康图像模板 | 一旦污染会破坏独立恢复依据 |

Peak首先划分位置区间。只有Peak超过可靠阈值且PSR超过模型更新阈值时，模型与尺度才获得许可。健康模板还要满足更高Peak以及连续稳定和刷新间隔。

### 3.4 Reliable、Weak和Lost三种置信度结果

Demo16当前真实默认配置为：

| 参数 | 当前值 | 作用 |
|---|---:|---|
| `lostThreshold` | `0.15` | Peak不高于该值时拒绝新位置 |
| `reliableThreshold` | `0.50` | Peak高于该值后才可能进入Reliable |
| `modelUpdatePsrThreshold` | `7.0` | 允许模型更新和尺度搜索的最低PSR |
| `recaptureAfterLostFrames` | `3` | 连续Lost达到3帧建议重捕获 |
| `recaptureAfterWeakFrames` | `5` | 连续Weak达到5帧拒绝继续漂移并建议重捕获 |

CC反编译流程中的可靠Peak参考值约为 `0.35`，当前Demo16为了降低误更新风险已经调为 `0.50`。文章和调参记录应分别标明“CC参考值”和“Demo当前值”。

以下代码来自Demo16的 `ConfidenceGuard::evaluate()` 第915—1022行。它只负责决策和连续计数，不直接修改图像、目标框或模型。

```cpp
/**
 * @brief 根据原尺度响应的Peak和PSR生成本帧操作许可。
 * @param peakValue 原尺度响应图最大值，用于划分位置置信度区间。
 * @param psrValue 原尺度响应图峰值旁瓣比，用于限制模型和尺度更新。
 * @return 包含状态等级、位置/尺度/模型许可、连续计数和重捕获建议。
 */
ConfidenceDecision ConfidenceGuard::evaluate(float peakValue, float psrValue)
{
    // 非有限分数无法与阈值可靠比较，直接拒绝继续更新内部计数器。
    if (!std::isfinite(peakValue) || !std::isfinite(psrValue)) {
        throw std::invalid_argument(
            "ConfidenceGuard::evaluate: values must be finite.");
    }

    // decision只保存判断结果；目标框和相关滤波模型由上层跟踪器根据许可修改。
    ConfidenceDecision decision;
    decision.peakValue = peakValue;
    decision.psrValue = psrValue;

    // 高Peak表示最佳候选具有足够强度，位置先获得许可。
    if (peakValue > config_.reliableThreshold) {
        decision.positionAllowed = true; // 高Peak位置先允许进入后续流程。
        decision.modelUpdateAllowed =
            psrValue > config_.modelUpdatePsrThreshold;
        decision.scaleSearchAllowed = decision.modelUpdateAllowed;
        decision.level = decision.modelUpdateAllowed
            ? ConfidenceLevel::Reliable
            : ConfidenceLevel::Weak;

        // 本帧已离开Lost区间，因此严重丢失计数归零。
        consecutiveLostFrames_ = 0;
        if (decision.modelUpdateAllowed) {
            // Peak和PSR同时达标，可靠状态连续性重新建立。
            consecutiveWeakFrames_ = 0;
        }
        else {
            ++consecutiveWeakFrames_; // Peak高但主峰不突出，仍按Weak累计。
        }
    }
    // Peak处于两个阈值之间时只暂时接受位置，尺度和模型均保持旧状态。
    else if (peakValue > config_.lostThreshold) {
        decision.level = ConfidenceLevel::Weak;
        decision.positionAllowed = true;  // 短暂Weak仍允许目标继续移动。
        decision.scaleSearchAllowed = false;
        decision.modelUpdateAllowed = false;
        consecutiveLostFrames_ = 0; // Weak帧会中断连续Lost。
        ++consecutiveWeakFrames_;   // 用于判断弱响应是否持续过久。
    }
    else {
        // Peak进入Lost区间后拒绝本帧候选位置，并开始累计连续Lost帧。
        decision.level = ConfidenceLevel::Lost;
        decision.positionAllowed = false; // 严重低分位置不写入内部框。
        decision.scaleSearchAllowed = false;
        decision.modelUpdateAllowed = false;
        ++consecutiveLostFrames_;
        consecutiveWeakFrames_ = 0;
    }

    // 单帧Weak仍允许位置延续；达到阈值后停止沿不可靠峰值继续漂移。
    const bool weakTooLong =
        consecutiveWeakFrames_ >= config_.recaptureAfterWeakFrames;
    if (weakTooLong) {
        // Weak持续过久后停止沿弱峰漂移，转而等待独立重捕获。
        decision.positionAllowed = false;
        decision.scaleSearchAllowed = false;
        decision.modelUpdateAllowed = false;
    }

    // 健康模板要求比普通位置接受更严格：必须处于Reliable且超过刷新Peak阈值。
    decision.healthyTemplateRefreshAllowed =
        decision.level == ConfidenceLevel::Reliable &&
        decision.modelUpdateAllowed &&
        peakValue > config_.healthyTemplateThreshold;

    // 连续Lost或持续Weak任一条件成立时，上层可以进入独立模板匹配恢复路径。
    decision.recaptureSuggested =
        consecutiveLostFrames_ >= config_.recaptureAfterLostFrames ||
        weakTooLong;
    return decision; // 返回许可和计数快照，本函数不直接执行尺度、训练或重捕获。
}
```

这套规则中的关键边界是：Weak并不立即等于丢失。短时Weak仍允许位置跟随，模型和尺度已经冻结；Weak持续过久后才拒绝位置并启动恢复路径。

## 4 Demo15的目标尺度估计

### 4.1 位置响应为什么不能直接得到目标宽高

相关滤波检测使用一张固定尺寸的FHOG特征图。无论原图目标框宽80像素还是100像素，搜索区域都会缩放到Demo12规定的固定输入尺寸，然后生成 $24\times24\times31$ 特征。响应峰值主要表示固定网格中的平移位置，不能仅凭峰值坐标直接求出目标宽高。

尺度估计需要主动提出几个不同大小的目标框，再比较哪一个框提取出的FHOG与历史模型更匹配。最直接的方法是每帧同时测试多个尺度，计算量会按尺度数量增长。Demo15采用CC风格的低成本近似：原尺度始终检测，每帧额外测试一个放大或缩小候选。

### 4.2 原尺度与放大、缩小候选框的构造

当前框为 $(c_x,c_y,w,h)$，尺度因子为 $s$，保持中心和宽高比的尺度候选为：

$$
w'=sw,\qquad h'=sh
$$

$$
x'=c_x-\frac{w'}{2},\qquad y'=c_y-\frac{h'}{2}
$$

Demo15默认 `scaleStep=1.1`：放大候选使用 $s=1.1$，缩小候选使用 $s=1/1.1\approx0.909$。成员 `nextScaleDirection_` 在 `+1` 和 `-1` 之间交替，因此相邻帧分别测试放大和缩小。

这意味着尺度最快只能逐帧按约10%改变，而且单帧只观察一个方向。它减少了一次FHOG提取和相关检测，代价是尺度快速变化时响应会慢一帧确认相反方向。

以下代码来自Demo15的 `ScaleFhogTracker::update()` 第1388—1436行。尺度候选先围绕已经完成位置更新的 `normalRect` 构造，再经过尺寸与画面边界保护。

```cpp
// 尺度搜索关闭时直接保留原尺度结果，避免额外一次FHOG提取和检测。
if (config_.enableScaleSearch) {
    // 记录本帧测试方向，供调试界面判断当前是在尝试放大还是缩小。
    result.testedScaleDirection = nextScaleDirection_;

    // 方向为+1时乘scaleStep；方向为-1时使用其倒数构造缩小候选。
    result.testedScaleFactor = nextScaleDirection_ > 0
        ? config_.scaleStep          // 本帧测试放大，默认1.1。
        : 1.0F / config_.scaleStep;  // 本帧测试缩小，默认约0.909。

    nextScaleDirection_ = -nextScaleDirection_; // 下一帧切换测试方向。

    // normalRect已经根据原尺度响应更新了中心；尺度变化保持这个中心不变。
    // scaleRectAroundCenter()同时缩放宽高并保持normalRect中心不变。
    cv::Rect2f scaleCandidateRect =
        scaleRectAroundCenter(normalRect, result.testedScaleFactor);

    // 第一步限制宽高范围，第二步整体移动矩形使其完整位于画面中。
    scaleCandidateRect = scale_tracker_demo::limitRectSize(
        scaleCandidateRect,
        frameSize_,
        config_.minimumTargetSize,
        config_.maximumTargetSize);
    scaleCandidateRect = scale_tracker_demo::clampRectToFrame(
        scaleCandidateRect, frameSize_);

    // 候选框决定原图搜索区域，提取器仍会把它缩放成固定FHOG几何。
    const cc_fhog_demo::CcFhogResult scaleFeature =
        featureExtractor_.extractFromFrame(frame, scaleCandidateRect);

    // 使用同一个历史model_检测尺度候选，得到可与原尺度Peak比较的响应分数。
    const response_detection_demo::DetectionResult scaleDetection =
        response_detection_demo::detectTarget(
            model_,
            scaleFeature.feature,
            config_.trackerConfig.psrExclusionRadius);

    // 暂存未经惩罚的候选Peak；是否切换尺度在后续比较中决定。
    result.scaleCandidatePeakValue = scaleDetection.peak.peakValue;
}
```

### 4.3 尺度惩罚为什么需要存在

原尺度和候选尺度都会生成一个Peak。直接选择较大的Peak会让细小随机差异不断触发尺度切换。Demo15先对候选尺度乘以 `scalePenalty=0.95`：

$$
score_{candidate}=peak_{candidate}\times0.95
$$

只有满足：

$$
score_{candidate}>peak_{normal}
$$

候选尺度才会被接受。假设原尺度Peak为 $0.70$，候选Peak为 $0.72$，惩罚后只有 $0.684$，框保持原尺寸；候选Peak至少超过约 $0.737$，惩罚后才可能战胜 $0.70$。

以下代码来自Demo15第1441—1505行。候选获胜后，还要使用候选尺度响应自己的位移结果更新中心。

```cpp
// 候选尺度先承担5%的切换成本，抑制宽高在相邻尺度间来回跳动。
result.penalizedScaleScore =
    result.scaleCandidatePeakValue * config_.scalePenalty;

// 候选承担惩罚后仍优于原尺度，才允许修改内部宽高。
if (result.penalizedScaleScore > result.normalPeakValue) {
    // scaleDetection来自候选搜索区域，其Cell位移必须使用scaleFeature自己的缩放关系换算。
    const cv::Point2f scaleImageDisplacement =
        response_detection_demo::featureDisplacementToImage(
            scaleDetection.peak.featureDisplacement,
            cv::Size(cellSize, cellSize),
            scaleFeature.searchPatch);

    // 把尺度候选响应得到的位置偏移叠加到候选框，形成尺度与中心都修正后的框。
    cv::Rect2f measuredScaleRect(
        scaleCandidateRect.x + scaleImageDisplacement.x,
        scaleCandidateRect.y + scaleImageDisplacement.y,
        scaleCandidateRect.width,
        scaleCandidateRect.height);

    // 先限制最小/最大尺寸，再把完整矩形移动回画面内。
    measuredScaleRect = limitRectSize(
        measuredScaleRect,
        frameSize_,
        config_.minimumTargetSize,
        config_.maximumTargetSize);
    measuredScaleRect = clampRectToFrame(measuredScaleRect, frameSize_);

    selectedRect = measuredScaleRect; // 底层内部框真正采用候选宽高和位置。
    // 最终Peak、PSR和响应图也应来自被选中的尺度检测结果。
    selectedDetection = scaleDetection;
    result.scaleChanged = true; // 告知上层本帧内部目标框宽高已经发生变化。
}
```

### 4.4 接受尺度后内部目标框怎样变化

尺度候选获胜后，`selectedRect` 会写入底层 `targetRect_`。下一帧的原尺度检测、搜索区域大小、位移换算和训练区域都从这个新框继续。这里更新的是跟踪器内部状态。

如果只把绘制矩形放大，内部仍使用旧框提取搜索区域，下一帧模型看到的目标比例不会改变。相反，如果把经过强平滑且明显滞后的显示框写回内部，搜索区域会持续落后于真实目标。因此Demo15采用：

```text
尺度检测结果
→ 写入内部原始目标框
→ 下一帧继续跟踪

同一个内部原始框
→ 复制给外部平滑器
→ 只生成稳定显示框
```

## 5 目标框尺寸限制、画面边界和外部平滑

### 5.1 尺寸限制与画面边界限制的区别

尺度候选可能连续缩小到低于有效FHOG目标尺寸，也可能放大到超过画面。两个函数分别处理不同问题：

- `limitRectSize()`：约束 `width` 和 `height`，并尽量保持中心；
- `clampRectToFrame()`：保持当前宽高，将 `x`、`y` 移动到画面允许范围。

Demo15默认最小尺寸为 $16\times16$。最大尺寸配置为0时，分别使用视频帧宽高作为上限。目标靠近右边界时，`clampRectToFrame()`会把矩形整体向左移动，宽度保持不变；直接裁掉越界部分会改变目标尺度，进而干扰下一帧跟踪。

以下代码来自Demo15的 `limitRectSize()` 和 `clampRectToFrame()` 第992—1135行核心部分。

```cpp
// 计算保持宽高比时所需的最小和最大统一缩放比例。
const float minimumScale = std::max(
    minimumSize.width / rect.width,
    minimumSize.height / rect.height);
const float maximumScale = std::min(
    maximumWidth / rect.width,
    maximumHeight / rect.height);

// 最小尺寸要求的放大倍数已经超过最大尺寸允许的倍数时，无法同时保持宽高比。
if (minimumScale > maximumScale + 1e-6F) {
    throw std::invalid_argument(
        "limitRectSize: constraints cannot preserve aspect ratio.");
}

// 默认比例1表示原尺寸已经位于允许范围内，后面的判断不会改变它。
float appliedScale = 1.0F;
if (minimumScale > 1.0F) {
    appliedScale = minimumScale; // 至少有一边过小，统一放大到满足最小尺寸。
}
if (maximumScale < appliedScale) {
    appliedScale = maximumScale; // 至少有一边过大，统一缩小到满足最大尺寸。
}

// 围绕原中心统一缩放宽高，避免尺寸限制引起目标中心跳动。
cv::Rect2f sizeLimitedRect = rectFromCenter(
    rectCenter(rect),
    cv::Size2f(rect.width * appliedScale, rect.height * appliedScale));

// 尺寸已经合法后，只限制左上角坐标，不再截短width和height。
const float maximumX = std::max(
    0.0F, static_cast<float>(frameSize.width) - sizeLimitedRect.width);
const float maximumY = std::max(
    0.0F, static_cast<float>(frameSize.height) - sizeLimitedRect.height);

// x、y分别限制到合法区间；宽高沿用已经完成尺寸限制的结果。
cv::Rect2f frameClampedRect(
    std::clamp(sizeLimitedRect.x, 0.0F, maximumX),
    std::clamp(sizeLimitedRect.y, 0.0F, maximumY),
    sizeLimitedRect.width,
    sizeLimitedRect.height);
```

### 5.2 统一缩放与宽高分别限制的区别

`scaleRectAroundCenter()`同时将宽高乘以同一个 $s$，所以尺度搜索本身保持宽高比。宽高比变化通常来自后处理、检测框融合或边界裁剪。

Demo15当前 `limitRectSize()`继续使用一个统一比例限制宽高。例如当前框是 $10\times40$、最小尺寸是 $16\times16$，统一放大比例为 $16/10=1.6$，结果为 $16\times64$，宽高比保持不变。

CC的 `limitBoxSize()` 更接近分别限制宽和高。同样输入可能得到 $16\times40$，此时宽高比发生变化。统一比例更适合保持任意区域初始形状；分别限制更直接，也能避免另一边被连带放大。文章复刻时必须把这两种策略标清，不能把Demo15的选择写成CC源码的完全等价行为。

### 5.3 内部跟踪框与外部显示框

内部框参与算法闭环：

```text
内部targetRect
→ 决定下一帧搜索区域
→ 决定FHOG缩放关系
→ 决定位移换算比例
→ 决定在线训练区域
```

外部显示框只消费内部结果，用于画面显示、云台控制前的稳定输出或上层接口。Demo15让一个底层 `ScaleFhogTracker` 生成唯一原始框，再把相同测量送给无平滑、指数平滑和Kalman平滑显示。这样三种显示方式比较的是同一次跟踪结果。

外围平滑不会修改FHOG模板、Alpha或底层尺度框。加强平滑后，绿色显示框抖动会减少，同时快速运动和快速远近变化会产生更明显滞后。

### 5.4 指数平滑与Kalman尺寸平滑

指数平滑只保存上一帧输出：

$$
s_t=(1-\alpha)s_{t-1}+\alpha z_t
$$

$z_t$ 是本帧测量宽高，$s_t$ 是平滑宽高。Demo15默认 `exponentialAlpha=0.35`，因此当前测量占35%，历史输出占65%。较小 $\alpha$ 更平稳，也更滞后。

Kalman尺寸平滑还维护宽高变化速度，状态为：

$$
[w,h,v_w,v_h]^T
$$

测量量为：

$$
[w_{measured},h_{measured}]^T
$$

Demo15当前配置为初始误差 `1.0`、过程噪声 `0.01`、测量噪声 `0.1`、时间间隔 `0.02`。过程噪声越小，滤波器越相信宽高按当前速度平稳变化；测量噪声越大，滤波器越少跟随单帧尺度测量，两种调整都会提高平滑程度并增加滞后。

以下代码来自Demo15的 `BoxSizeStabilizer::update()` 第869—941行。

```cpp
/**
 * @brief 根据配置返回本帧用于外部显示的稳定宽高。
 * @param measuredSize 底层尺度跟踪器输出的原始宽高，单位为原图像素。
 * @return None、指数平滑或Kalman修正后的显示宽高；不会写回底层目标框。
 */
cv::Size2f BoxSizeStabilizer::update(const cv::Size2f& measuredSize)
{
    // update()依赖reset()/initialize()建立的历史状态，未初始化时不能预测。
    if (!initialized_) {
        throw std::logic_error(
            "BoxSizeStabilizer::update: stabilizer is not initialized.");
    }
    // 宽高必须为有限正数，否则指数或Kalman状态会被非法测量污染。
    if (!isValidSize(measuredSize)) {
        throw std::invalid_argument(
            "BoxSizeStabilizer::update: measuredSize is invalid.");
    }

    // None模式作为对照组，直接把本帧测量保存为下一帧历史值。
    if (config_.mode == SizeStabilizerMode::None) {
        stableSize_ = measuredSize; // 直接显示底层测量宽高。
        return stableSize_;
    }

    // 指数模式只融合上一帧稳定值与当前测量，不估计宽高变化速度。
    if (config_.mode == SizeStabilizerMode::Exponential) {
        const float alpha = config_.exponentialAlpha;

        // alpha是当前测量权重，1-alpha是历史稳定值权重。
        stableSize_.width =
            (1.0F - alpha) * stableSize_.width + alpha * measuredSize.width;
        stableSize_.height =
            (1.0F - alpha) * stableSize_.height + alpha * measuredSize.height;
        return stableSize_;
    }

    // Kalman模式先根据上一帧[w,h,vw,vh]预测本帧宽高及变化速度。
    kalmanFilter_.predict();

    // 测量向量只包含底层跟踪器本帧给出的width和height。
    const cv::Mat measurement =
        (cv::Mat_<float>(2, 1) << measuredSize.width, measuredSize.height);

    // correct()使用当前测量修正预测状态，并把修正结果保存进KalmanFilter内部。
    const cv::Mat correctedState = kalmanFilter_.correct(measurement);

    // correct()输出[w,h,vw,vh]，显示层只读取前两个分量。
    stableSize_.width = std::max(correctedState.at<float>(0, 0), 1.0F);
    stableSize_.height = std::max(correctedState.at<float>(1, 0), 1.0F);
    return stableSize_; // 返回值只交给显示或上层控制，不修改ScaleFhogTracker。
}
```

Kalman能够利用速度预测短时趋势，但它没有观察图像内容。目标真正丢失后，滤波器只能继续推测宽高或位置，无法依靠运动模型重新辨认目标。

## 6 遮挡期间的模型冻结与健康模板

### 6.1 模板怎样从目标逐渐污染成遮挡物

模板污染通常经过三个阶段。

第一阶段是响应偏移。树枝进入目标框后，FHOG中增加了大量强方向边缘，最高响应位置可能逐渐偏向树枝。第二阶段是位置接受。Peak仍高于最低阈值时，程序把偏移框作为当前目标位置。第三阶段是模型更新。新位置上的FHOG被反复插入历史模板，模型开始主动偏好树枝。

这说明“目标被树枝遮挡后很快进入重捕获”和“目标框仍处于普通KCF跟踪”需要通过实际状态字段判断。只要 `positionAllowed=true`，底层仍在使用FHOG响应移动；只要 `modelUpdateAllowed=true` 且累计到更新间隔，模型还会发生变化。界面应同时显示状态、Peak、PSR、位置许可和更新许可。

高置信度漂移是最难处理的情况：错误背景产生了高Peak和高PSR，常规门控会误认为结果可靠。运动约束、前景分割、YOLO辅助或更强的深度特征可以继续降低风险，但纯相关滤波无法仅凭一张响应图完全确认目标身份。

### 6.2 位置、尺度和模型为什么需要分别冻结

不同操作造成错误后的代价不同：

- 接受一次位置：下一帧搜索中心会偏移，但旧模型仍可能把目标拉回来；
- 接受一次错误尺度：搜索区域与目标比例改变，后续响应和位移换算都会受影响；
- 更新一次错误模型：背景特征进入长期状态，影响会跨越多帧；
- 刷新一次错误健康模板：独立恢复依据也被覆盖，重捕获会继续寻找错误背景。

因此Demo16采用分级冻结：

| 状态 | 位置 | 尺度 | FHOG模型 | 健康模板 |
|---|---|---|---|---|
| Reliable | 接受 | 允许 | 按间隔更新 | 还需更严格条件 |
| 短暂Weak | 暂时接受 | 冻结 | 冻结 | 冻结 |
| Weak持续过久 | 拒绝 | 冻结 | 冻结 | 保留 |
| Lost | 拒绝 | 冻结 | 冻结 | 保留 |

以下代码来自Demo16第1690—1768行核心部分。严重低分时，程序保存上一帧内部框，旧模型和健康模板均保持不变。

```cpp

    modelUpdateEligibleFrameCount_ = 0; // 可靠更新必须重新连续累计。
}

// 位置许可失败时进入冻结路径，本帧不会执行后面的尺度和在线训练。
if (!result.confidence.positionAllowed) {
    targetRect_ = previousRect; // 拒绝候选位置，内部搜索中心停留在上一帧。
    result.positionAccepted = false;
    result.scaleChanged = false;

    // 只有连续Weak/Lost达到门槛且存在健康模板时，才进入独立重捕获路径。
    if (config_.enableRecapture &&
        result.confidence.recaptureSuggested &&
        !healthyTemplate_.empty()) {
        // 使用独立健康图像模板在最后可靠位置附近搜索，避免继续依赖退化FHOG模型。
        const LocalRecaptureResult recapture =
            matchHealthyTemplateLocally(
                frame,
                healthyTemplate_,
                lastReliableRect_,
                config_.recaptureConfig);
        // 把是否真正执行匹配及其分数交给上层显示；attempted=false不等于低分失败。
        result.recaptureAttempted = recapture.attempted;
        result.recaptureScore = recapture.matchScore;
    }
}
```

### 6.3 FHOG模型与健康图像模板的区别

Demo16同时保存两类“模板”，名称接近但职责不同。

| 对象 | 数据 | 每帧怎样使用 | 怎样更新 |
|---|---|---|---|
| FHOG相关滤波模型 | `templateFeature`和`alphaSpectrum` | 每帧产生响应图和目标位移 | 可靠帧累计到间隔后小学习率插值 |
| 健康图像模板 | 原图目标ROI的 `cv::Mat` | 丢失后交给 `matchTemplate()` | 极高置信度连续稳定且达到刷新间隔后覆盖 |

`modelImageTemplate_` 只是最近一次被FHOG模型吸收的原图区域，用于调试观察。31通道FHOG无法简单反向还原成一张原图，所以右上角显示的图像样本只能说明“最近用哪个区域训练过”，不能逐像素代表内部模型内容。

健康模板的作用是保留一个更保守的视觉快照。FHOG模型可以缓慢适应外观，健康模板以更低频率更新，丢失时提供相对独立的恢复依据。

### 6.4 健康模板的刷新条件

当前Demo16刷新健康模板需要同时满足：

$$
peak>0.60
$$

$$
PSR>7.0
$$

并且连续满足5帧，距离上次刷新至少15帧。只要中间一帧不满足条件，连续稳定计数清零。

以下代码来自Demo16第2027—2076行。

```cpp
++framesSinceHealthyTemplateRefresh_; // 每帧记录距离上次健康模板刷新的时间。

// 门控许可包含Reliable和Peak条件，此处再叠加健康模板专用PSR阈值。
const bool healthyTemplateCandidate =
    result.confidence.healthyTemplateRefreshAllowed &&
    normalDetection.peak.psr >= config_.healthyTemplatePsrThreshold;

if (healthyTemplateCandidate) {
    ++healthyTemplateStableCount_; // Peak与PSR同时满足时连续累计。
}
else {
    healthyTemplateStableCount_ = 0; // 任一条件失败都要重新累计稳定帧。
}

// 两个条件分别限制“连续可靠程度”和“两次刷新之间的最短时间”。
const bool stableLongEnough =
    healthyTemplateStableCount_ >= config_.healthyTemplateStableFrames;
const bool refreshIntervalPassed =
    framesSinceHealthyTemplateRefresh_ >=
    config_.healthyTemplateRefreshInterval;

// 同时满足稳定帧数和刷新间隔后，才允许读取当前目标ROI。
if (stableLongEnough && refreshIntervalPassed) {
    // clone动作封装在extractTargetImage()中，新模板不会引用随后复用的视频帧内存。
    cv::Mat newHealthyTemplate = extractTargetImage(frame, targetRect_);

    // ROI为空时保持旧健康模板，避免一次边界异常破坏恢复依据。
    if (!newHealthyTemplate.empty()) {
        // move转移新矩阵所有权，旧healthyTemplate_在赋值时释放。
        healthyTemplate_ = std::move(newHealthyTemplate);
        lastReliableRect_ = targetRect_; // 重捕获搜索区也改用本次可靠位置。
        result.healthyTemplateRefreshed = true;
        // 本轮刷新完成，连续稳定帧和间隔帧都从0重新累计。
        healthyTemplateStableCount_ = 0;
        framesSinceHealthyTemplateRefresh_ = 0;
    }
}
```

条件过严时，人物转身或车辆视角变化后，健康模板仍保留很早的外观，重捕获匹配分数会降低；条件过松时，短时树枝遮挡可能覆盖模板。调参时应分别记录 `peak`、`PSR`、刷新时刻和右上角健康模板图像，不能只观察最终绿色框。

## 7 Demo16的局部模板匹配重捕获

### 7.1 为什么重捕获使用独立健康模板

相关滤波模型在正常状态下速度快，也能适应小位移。连续Weak或Lost说明当前模型已经无法提供稳定位置。继续扩大同一个KCF搜索区域仍会受到当前FHOG模型的外观偏差影响，而且更大FHOG搜索会增加缩放失真和计算量。

Demo16选择一条简单恢复路径：保存高置信度目标ROI，丢失后在最后可靠位置附近用OpenCV模板匹配。它与FHOG模型使用不同的数据和匹配方式，因此能够在FHOG响应退化时提供一次独立候选。代价是原图模板对姿态、尺度和旋转变化更敏感。

### 7.2 局部搜索区域怎样根据目标大小选择

局部重捕获以 `lastReliableRect_` 为中心。当前配置根据目标最大边选择搜索尺寸：

| 目标最大边 | 期望搜索区域 |
|---:|---:|
| 不超过64像素 | $256\times256$ |
| 大于64且不超过160像素 | $512\times512$ |
| 大于160像素 | 最大 $640\times512$ |

搜索区域至少能容纳健康模板，且不能超过当前视频帧。靠近画面边缘时，程序整体移动搜索矩形，尽量保留规定搜索尺寸。

以下代码来自Demo16的 `computeLocalSearchWindow()` 第1080—1166行核心部分。

```cpp
// 目标最大边用于把当前目标划分为小、中、大三档搜索范围。
const float targetMaximumSide =
    std::max(referenceRect.width, referenceRect.height);

cv::Size desiredSearchSize; // 保存按目标档位选择的期望搜索宽高。
if (targetMaximumSide <= config.smallTargetMaximumSide) {
    desiredSearchSize = config.smallSearchSize;       // 默认256×256。
}
else if (targetMaximumSide <= config.mediumTargetMaximumSide) {
    desiredSearchSize = config.mediumSearchSize;      // 默认512×512。
}
else {
    desiredSearchSize = config.largeSearchSize;       // 默认640×512。
}

// 搜索区至少要能放下目标模板，同时不得超过实际画面。
// std::max保证模板本身一定能完整放进搜索区域。
desiredSearchSize.width = std::max(
    desiredSearchSize.width, static_cast<int>(std::ceil(referenceRect.width)));
desiredSearchSize.height = std::max(
    desiredSearchSize.height, static_cast<int>(std::ceil(referenceRect.height)));
// std::min把搜索宽高限制到实际视频帧，避免后续ROI越界。
const int searchWidth = std::min(desiredSearchSize.width, frameSize.width);
const int searchHeight = std::min(desiredSearchSize.height, frameSize.height);

// 以最后可靠框中心为局部搜索中心，先计算期望搜索框左上角。
const cv::Point2f center = rectCenter(referenceRect);
int searchX = cvRound(center.x - searchWidth * 0.5F);
int searchY = cvRound(center.y - searchHeight * 0.5F);

// 越过边界时移动整个搜索框，保持宽高不被边界裁短。
searchX = std::clamp(searchX, 0, frameSize.width - searchWidth);
searchY = std::clamp(searchY, 0, frameSize.height - searchHeight);

// 返回完全位于原图内的整数ROI，供matchTemplate()直接截取。
return cv::Rect(searchX, searchY, searchWidth, searchHeight);
```

### 7.3 TM_CCOEFF_NORMED怎样计算匹配分数

`TM_CCOEFF_NORMED` 是OpenCV模板匹配的一种归一化相关系数。模板 $T$ 在搜索区域位置 $(x,y)$ 对应的候选块为 $I_{x,y}$，先分别减去各自均值：

$$
T'=T-\bar{T}
$$

$$
I'=I_{x,y}-\bar{I}_{x,y}
$$

再计算：

$$
R(x,y)=
\frac{\sum T'I'}
{\sqrt{\sum {T'}^2\sum {I'}^2}}
$$

减均值削弱整体亮度偏移，分母归一化削弱整体对比度大小差异。结果越接近1，候选块与模板的相对纹理变化越一致；接近0表示线性相关较弱；负值表示变化方向相反。

以下代码来自Demo16的 `matchHealthyTemplateLocally()` 第1203—1269行核心部分。

```cpp
LocalRecaptureResult result; // 默认attempted=false、success=false，失败路径保留这些状态。

// 根据目标尺寸和最后可靠框计算原图坐标中的局部搜索ROI。
result.searchRect = computeLocalSearchWindow(
    lastReliableRect, frame.size(), config);

// 搜索区无法容纳健康模板时保持attempted=false，调用者不能把它当作匹配失败分数。
if (healthyTemplate.cols > result.searchRect.width ||
    healthyTemplate.rows > result.searchRect.height) {
    return result;
}

// 搜索区能够容纳模板后，才把本次操作标记为真正尝试过匹配。
result.attempted = true;

// searchPatch是frame的只读ROI视图；其坐标原点位于result.searchRect左上角。
const cv::Mat searchPatch = frame(result.searchRect);

// 计算健康模板在搜索ROI每个合法左上角位置的归一化相关系数。
cv::matchTemplate(
    searchPatch,
    healthyTemplate,
    result.response,
    cv::TM_CCOEFF_NORMED);

double maximumScore = -1.0; // 保存TM_CCOEFF_NORMED响应图最大值。
cv::Point maximumLocation;  // 保存最大值在局部搜索ROI中的整数坐标。

// 只需要最大值及其位置，最小值参数传nullptr忽略。
cv::minMaxLoc(
    result.response,
    nullptr, &maximumScore,
    nullptr, &maximumLocation);

// 将OpenCV输出写入结果，并用配置阈值判断该候选是否可以进入模型重建。
result.matchScore = static_cast<float>(maximumScore);
result.matchLocationInSearch = maximumLocation;
result.success = result.matchScore >= config.matchThreshold;

if (result.success) {
    // 最大值坐标属于局部搜索图，需要加上searchRect左上角转换为原图坐标。
    result.recoveredRect = cv::Rect2f(
        static_cast<float>(result.searchRect.x + maximumLocation.x),
        static_cast<float>(result.searchRect.y + maximumLocation.y),
        static_cast<float>(healthyTemplate.cols),
        static_cast<float>(healthyTemplate.rows));
}
```

### 7.4 匹配阈值与错误重捕获

Demo16当前 `matchThreshold=0.60`。阈值提高会减少相似背景误捕，同时增加人物姿态改变、车辆视角改变或尺度变化后的漏捕；阈值降低会更容易恢复，也更容易将树枝、道路纹理或相似车辆作为目标。

模板匹配本身不理解“人”或“车”。它只比较矩形图像中的相对像素纹理。健康模板中如果包含背景，背景同样参与分数；目标尺寸改变时，Demo16也没有对模板执行尺度金字塔搜索。

更稳妥的重捕获可以追加以下验证，但这些属于后续扩展：

- 恢复框与最后可靠位置的中心距离不能超过运动允许范围；
- 匹配模板的宽高与当前尺度趋势不能突然变化；
- 在恢复框重新计算FHOG响应，要求Peak与PSR达到恢复门槛；
- 有YOLO时验证类别和检测置信度。

### 7.5 重捕获成功后的模型重建

模板匹配只产生一个候选矩形。旧FHOG模型的搜索中心、模板特征和Alpha仍属于丢失前状态。恢复成功后必须在新矩形处重新提取FHOG并训练完整模型。

以下代码来自Demo16第1779—1803行。`rebuildModel()` 成功后还会重置置信度计数，下一帧从恢复框继续检测。

```cpp
// 只有模板匹配分数达到阈值时，才允许使用恢复框影响跟踪器状态。
if (recapture.success) {
    // 在恢复位置重新提取FHOG并训练模型；旧模板和Alpha由新模型替换。
    // 第三个参数false表示本次重建不覆盖健康模板，先保留原来的可靠恢复依据。
    if (rebuildModel(
            frame,
            recapture.recoveredRect,
            false)) {
        // rebuildModel()成功表示新位置上的FHOG、Alpha和内部框已经全部建立。
        result.recaptured = true;
        result.modelReinitialized = true;
        result.positionAccepted = true;

        // 再次执行合法化作为输出边界保护，并将该位置设为新的恢复中心。
        targetRect_ = legalizeRect(
            recapture.recoveredRect,
            frameSize_);
        lastReliableRect_ = targetRect_;
    }
}
```

这里的 `false` 表示模型重建时暂不覆盖健康模板。重捕获只是达到了较低的模板匹配门槛，还没有经过连续多帧的高Peak和高PSR验证；立即覆盖健康模板会放大一次误捕造成的影响。

## 8 Demo14至Demo16的递进验证与实现边界

### 8.1 Demo14验证模型是否真正在线更新

Demo14先自动验证学习率边界：$\eta=0$ 后模型与旧模型完全一致，$\eta=1$ 后模型与当前模型一致，$\eta=0.25$ 后结果应等于OpenCV `addWeighted()` 的25%插值。

真实视频部分使用相同初始框对比固定模型、`0.02`和更大学习率。控制台中的 `templateChangeL2` 与 `alphaChangeL2` 用于证明模型是否真正改变；只观察目标框无法分辨“固定模型仍然跟住”和“在线模型已经更新”。

### 8.2 Demo15验证内部尺度与外部平滑

Demo15只运行一个底层 `ScaleFhogTracker`。同一个 `measuredRect` 分别生成无平滑、指数平滑和Kalman平滑显示框。验证时需要观察：

- 目标靠近时，内部原始框是否逐步放大；
- `testedScaleDirection` 是否逐帧在放大和缩小之间交替；
- `penalizedScaleScore` 是否真正战胜 `normalPeakValue`；
- 外部平滑框是否降低抖动，以及产生多少滞后；
- 画面边缘处内部框是否仍完整合法。

### 8.3 Demo16验证置信度冻结与局部恢复
