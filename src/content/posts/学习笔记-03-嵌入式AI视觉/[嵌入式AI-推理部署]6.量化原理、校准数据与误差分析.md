# 阶段4-6 量化原理、校准数据与误差分析

本文前四章主要解释量化原理：模型中的什么数值会被量化、浮点数怎样映射为低位宽整数，以及整数推理为什么能够减少存储和计算开销。第5章开始进入量化方案与框架配置，第6章解释权重统计和激活校准，最后再用PyTorch、ONNX Runtime与RKNN Toolkit2完成实际模型量化。学习前面的公式时，重点是理解框架在内部完成了什么；实际项目通常调用框架接口，不需要手写逐元素量化程序。

## 1 什么是AI模型量化

AI模型量化（Quantization）是用数量有限的低位宽数值近似模型中的高精度浮点数，并让推理框架在支持的算子上使用这些低位宽数值完成存储、传输或计算。本文主要比较32位浮点数（32-bit Floating Point，FP32）、16位浮点数（FP16）和8位有符号整数（8-bit Integer，INT8）。

理解量化之前，可以先把一个模型看成一条数值处理链。图片进入模型后，每一层读取上一层给出的数字，用训练得到的参数进行计算，再把一组新数字交给下一层。量化改变的正是这条处理链中的数字表示方式。

例如，一个卷积层原来保存了浮点权重 `0.8127`、`-0.1364` 和 `0.0241`。转换成INT8模型时，量化工具会把它们映射到有限的整数刻度，例如 `81`、`-14` 和 `2`，同时保存一组用于解释这些整数的量化参数。推理框架读取整数及量化参数后，仍然能够近似表达原来的浮点数值。

量化的目标是减少模型存储、内存访问和计算开销。低位宽表示会丢失一部分数值信息，因此模型体积、推理速度和精度需要一起测量。

### 1.1 AI模型中参与量化的权重、激活值、输入与输出

模型推理时主要会接触四类数值：

- **权重（Weight）**：训练完成后保存在模型文件中的参数，例如卷积核和全连接层权重。模型执行一次推理时，权重通常保持不变。
- **激活值（Activation）**：输入经过某一层计算后得到的中间结果。激活值会随输入变化，例如白天道路图片和夜间道路图片可能产生不同的特征响应范围。
- **模型输入**：送入第一个算子的张量。它可能是经过缩放、颜色转换和归一化后的图像数据。
- **模型输出**：最后一个或几个输出节点产生的张量。YOLO目标检测模型（已在阶段3-5中介绍）的输出通常还要经过置信度计算、边框解码和非极大值抑制等后处理。

这些数值在量化中的处理方式并不完全相同。权重已经固定，量化工具可以直接读取并统计它的最大值、最小值和分布。激活值需要让模型实际处理输入数据后才能观察，因此静态INT8量化通常需要校准数据。第6节会完整解释校准过程。

模型也不一定从输入到输出全部使用INT8。部署工具会根据硬件支持和精度要求决定哪些张量保留FP32或FP16，哪些张量转换为INT8。某些算子前后还会插入量化与反量化节点，形成浮点计算和整数计算混合的数据链。

### 1.2 从连续浮点数值到有限整数刻度的近似表示

一组FP32数值可以在很大的范围内取值，并且能够表示大量小数。INT8只有8个二进制位：

- 有符号INT8的编码范围是 (-128) 到 (127)，一共256个整数编码；
- 无符号UINT8的编码范围是 (0) 到 (255)，同样有256个整数编码。

量化工具需要用这256个编码覆盖某段浮点范围。假设要表示的浮点范围是 (-1.0) 到 (1.0)，可以把这段范围切成许多离散刻度。原始浮点值会落到距离最近的刻度上。

例如，相邻刻度之间相差 `0.1` 时，`0.31` 可以近似为 `0.3`，`0.36` 可以近似为 `0.4`。两个浮点值也可能落到同一刻度，例如 `0.31` 和 `0.33` 都可能被表示成 `0.3`。这种由有限刻度产生的差异就是量化误差的一部分。

量化参数负责说明“一个整数刻度代表多少浮点数值”以及“浮点数0对应哪个整数”。因此，单独看到INT8编码 `3` 没有完整意义；还要结合它所在张量的缩放因子和零点，才能知道它近似表示哪个浮点值。

### 1.3 量化对模型存储、数据传递和推理计算的改变

量化可能同时改变三个环节：

1. **模型存储**：权重由FP32转换为INT8后，每个权重从4字节降到1字节。
2. **张量传递**：相邻量化算子之间可以传递INT8激活，减少中间张量占用和内存带宽。
3. **算子计算**：硬件和推理框架支持时，卷积、矩阵乘法等算子可以使用整数计算内核。

网络层的连接关系和模型任务通常保持原样。例如，量化后的YOLO仍然包含骨干网络、特征融合结构和检测头，也仍然输出类别与边框相关张量。变化集中在权重、激活以及算子计算采用的数值格式。

在ONNX模型中，量化结果常见两种表达形式：

- **QOperator形式**：把原算子替换为带量化语义的算子，例如 `Conv` 对应 `QLinearConv`。
- **QDQ形式**：在原算子周围插入量化（Quantize）和反量化（Dequantize）节点，因此简称QDQ。ONNX中的具体节点名为 `QuantizeLinear` 和 `DequantizeLinear`，量化参数保存在这些节点中。

这两种形式描述的是量化模型怎样写入ONNX计算图。目标推理后端支持哪一种，应以它的官方说明为准。ONNX Runtime当前同时说明了QOperator和QDQ形式，并将QDQ作为静态量化可选的模型表示方式，参见[ONNX Runtime官方量化文档](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)。

## 2 模型量化对部署资源与推理性能的影响

嵌入式设备经常同时受模型存储空间、运行内存、内存带宽、推理延迟和功耗限制。量化能够降低其中一部分成本，这也是部署阶段需要学习量化的直接原因。

### 2.1 FP32、FP16与INT8的位宽和参数存储量

FP32、FP16和INT8分别使用32位、16位和8位表示一个数值，也就是4字节、2字节和1字节。

假设模型只包含一亿个参数，并暂时忽略模型结构、量化参数和文件格式带来的额外数据：

| 权重格式 | 每个参数字节数 | 一亿个参数的理论存储量 |
| --- | ---: | ---: |
| FP32 | 4 | 约400 MB |
| FP16 | 2 | 约200 MB |
| INT8 | 1 | 约100 MB |

这里的比例只适用于相同数量的纯参数。实际ONNX文件还会保存节点、张量形状、名称、`scale`、`zero-point`，并且部分算子可能继续使用浮点权重，所以文件大小不会严格等于表中的数值。

FP32可以表示很大的动态范围和较细的小数变化，适合训练和建立精度基线。FP16减少了浮点数的指数位和尾数位，常用于支持半精度计算的GPU或NPU。INT8只保存256种整数编码，需要配合量化参数解释原始数值，压缩更明显，数值近似误差也更需要验证。

### 2.2 整数计算对内存带宽、缓存和硬件计算单元的影响

模型推理耗时不只来自乘法和加法。处理器还要从内存读取权重，把中间激活写回内存，再让后续算子读取。

同一组权重从FP32缩小到INT8后，一次内存传输能够携带约4倍数量的参数。缓存容量固定时，也能容纳更多INT8权重。例如，1 MB缓存最多容纳约26万个FP32数值或约104万个INT8数值，这里按 1MB=1,048,576 字节计算。

如果处理器提供INT8向量指令或NPU整数计算单元，一个指令周期内还可能处理更多数据。模型因此可能同时减少内存等待和计算时间。

### 2.3 推理加速受硬件、算子和量化内核支持限制

INT8模型没有固定加速倍数。最终速度由以下条件共同决定：

- 目标处理器是否具有高效的INT8计算单元；
- 推理框架是否为当前算子、形状和张量布局提供INT8内核；
- 模型中有多少计算真正落在INT8内核上；
- 量化、反量化和张量格式转换增加了多少开销；
- 模型瓶颈来自计算、内存还是其他操作。

例如，一个模型虽然保存为QDQ形式，但目标后端不支持其中某个量化算子。推理框架可能把该算子放回CPU执行，或在它前后转换数据格式。频繁的数据转换会抵消部分加速收益。

因此，部署时至少要分别测量模型文件大小、峰值内存、端到端延迟和任务精度。ONNX Runtime官方文档也明确指出，量化性能收益依赖模型与硬件，老旧硬件甚至可能因为量化和反量化开销而变慢，参见[量化性能说明](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html#why-am-i-not-seeing-performance-improvements)。

## 3 浮点张量量化为INT8张量的完整过程

这一节只处理一个张量，先把浮点数如何变成整数讲清楚。模型中的权重和激活量化都会复用同一套线性映射关系。

### 3.1 浮点范围、整数范围与离散量化刻度

量化的第一步是确定准备覆盖的浮点范围。用 $x_{\min}$ 和 $x_{\max}$ 表示浮点张量的下界和上界，用 $q_{\min}$ 和 $q_{\max}$ 表示整数编码下界和上界。

例如，UINT8范围是0到255。如果要覆盖的浮点范围是 (-1.0) 到 (2.0)，总宽度为3.0。256个编码之间包含255段间隔，因此每相邻两个整数编码代表的浮点间隔为：

\[
\frac{2.0-(-1.0)}{255-0}=\frac{3}{255}\approx0.0117647
\]

浮点范围越宽，每个整数刻度覆盖的间隔越大，普通数值的近似会越粗。浮点范围过窄时，落在范围外的数值会被截断到边界。这形成一个直接取舍：

- 扩大范围可以容纳极端值，但中间区域刻度变粗；
- 缩小范围可以细分常见数值，但极端值更容易饱和。

量化算法和校准数据共同决定怎样处理这个取舍。

### 3.2 scale与zero-point的含义和计算

缩放因子（Scale）表示相邻两个整数编码对应的浮点间隔，必须是正数。零点（Zero Point）表示浮点数0映射到哪个整数编码。

在线性非对称量化中，缩放因子常按下式计算：

\[
s=\frac{x_{\max}-x_{\min}}{q_{\max}-q_{\min}}
\]

其中：

- $s$ 是缩放因子；
- $x_{\min}$、$x_{\max}$ 是准备覆盖的浮点范围；
- $q_{\min}$、$q_{\max}$ 是整数编码范围。

零点可以按下式计算，再限制到整数范围：

\[
z=\operatorname{clip}\left(
\operatorname{round}\left(q_{\min}-\frac{x_{\min}}{s}\right),
q_{\min},q_{\max}
\right)
\]

零点需要让浮点数0能够被准确表示。卷积神经网络经常使用零填充，如果0经过量化和反量化后变成一个非零数，填充区域就会向卷积计算引入额外偏差。

仍以浮点范围 $[-1.0,2.0]$ 和UINT8范围 $[0,255]$ 为例：

\[
s=\frac{3}{255}\approx0.0117647
\]

\[
z=\operatorname{round}\left(0-\frac{-1.0}{0.0117647}\right)=85
\]

因此，UINT8编码85近似表示浮点数0。编码每增加1，对应浮点值增加约0.0117647。

### 3.3 量化与反量化公式的逐步计算

已知缩放因子 $s$ 和零点 $z$ 后，浮点值 $x$ 量化为整数 $q$ 的公式是：

\[
q=\operatorname{clip}\left(
\operatorname{round}\left(\frac{x}{s}\right)+z,
q_{\min},q_{\max}
\right)
\]

每一步的作用如下：

1. $x/s$：计算浮点值距离0有多少个量化刻度；
2. `round`：把刻度位置舍入到整数；
3. 加上 $z$：移动到实际整数编码位置；
4. `clip`：将结果限制在整数类型能够表示的范围内。

反量化把整数编码恢复成近似浮点值：

\[
\hat{x}=s(q-z)
\]

其中 $\hat{x}$ 是恢复后的近似值。仍使用 $s\approx0.0117647$、$z=85$，量化浮点值 $x=0.4$：

\[
q=\operatorname{round}\left(\frac{0.4}{0.0117647}\right)+85
=34+85=119
\]

反量化结果为：

\[
\hat{x}=0.0117647\times(119-85)\approx0.4
\]

有些数值恰好靠近刻度，因此恢复误差很小；更多数值会落在两个刻度之间，反量化后只能得到邻近值。

### 3.4 舍入误差、数值截断与饱和误差

舍入误差发生在数值位于两个整数刻度之间时。假设 $s=0.1,z=0$，浮点值 `0.26` 对应2.6个刻度，舍入后得到整数3，反量化结果为 `0.3`，绝对误差为 `0.04`。

饱和误差发生在量化结果超出整数范围时。仍使用 $s=0.1,z=0$ 和INT8范围 $[-128,127]$，能够覆盖的反量化范围是：

\[
[-128\times0.1,127\times0.1]=[-12.8,12.7]
\]

浮点值 `20.0` 量化前对应整数200，INT8无法保存该值，`clip`会把它限制为127。反量化后得到 `12.7`，误差达到 `7.3`。

舍入误差通常较小并分布在许多数值上，饱和误差会让超出范围的数值全部堆积在边界。调试INT8模型时，观察某层有多少激活落在上下界，可以帮助判断该层量化范围是否过窄。

## 4 权重、激活值和模型输入输出的量化过程

单个张量的映射规则已经确定，接下来把它放回模型执行流程。权重和激活都能使用第3节的公式，但它们的数值来源不同，量化参数的获取方式也不同。

### 4.1 权重量化处理模型中的固定参数

训练结束后，卷积层权重已经保存在模型文件中。量化工具可以逐个读取权重张量，统计其范围，再计算量化参数。

例如，某个卷积核权重范围为 $[-0.8,0.7]$。量化工具可以直接根据该范围生成 `scale` 和 `zero-point`，把FP32权重转换成INT8编码，并把编码与量化参数写入模型文件。整个过程不需要输入图片，因为权重不会随图片改变。

权重量化直接减少模型文件和权重读取量。仅量化权重时，推理框架仍可能在计算前把权重恢复为浮点，或者使用支持权重低位宽的专用内核。具体执行方式由目标后端决定。

### 4.2 激活量化处理中间层的运行时数据

激活量化并非所有模型都会采用。它处理的是卷积、矩阵乘法、激活函数和特征融合等运算产生的中间张量，目标是让中间数据和支持的算子进入低位宽计算路径。

视觉CNN和较小模型经常部署到CPU、DSP或NPU，这些后端通常提供成熟的INT8卷积与矩阵乘法内核，因此常见W8A8：权重使用8位，激活也使用8位。激活量化可以降低中间张量带宽，并让更多算子使用整数内核。

当前大语言模型部署更常见混合方式。大量线性层权重使用4位或8位，激活继续使用FP16或BF16，少量敏感层还可以保留更高精度。这类W4A16或W8A16方案主要缓解模型文件、显存和权重带宽压力。大模型也存在动态W8A8等权重与激活同时量化方案，因此模型类型只能说明常见路线，最终选择仍由后端内核、精度和性能目标决定。TorchAO同时提供权重专用配置和动态激活配置，参见[TorchAO量化推理工作流](https://docs.pytorch.org/ao/stable/workflows/inference.html)。

激活值由“当前输入 + 当前权重 + 前面各层结果”共同决定。采用激活量化后，还要决定量化参数是转换时固定，还是每次推理时计算。第4.3节先说明两种方式共有的数据变化，第5.4节再比较静态和动态方案。

### 4.3 激活值的量化、反量化与整数计算流程

这一节主要说明激活值量化时具体发生什么。上一层先产生浮点激活，量化操作把它映射为低位宽整数；需要回到浮点算子或模型输出时，反量化再根据 `scale` 和 `zero-point` 恢复近似浮点值：

```text
上一层浮点激活
→ QuantizeLinear：按scale和zero-point转换为INT8
→ DequantizeLinear：把INT8恢复为近似浮点值
→ 浮点算子继续读取这个近似值
```

这是ONNX QDQ模型用于表达量化影响的直观形式。反量化后的数值与原值之间会保留第3.4节介绍的舍入或饱和误差。

真正使用整数内核时，推理框架可以把相邻的量化、反量化和算子融合起来。卷积的常见执行流程是：

```text
上一层浮点激活量化为INT8
→ 与INT8权重相乘
→ 乘加结果累积到INT32
→ 按下一层的量化参数重新量化为INT8
→ 下一量化算子继续使用INT8，或在浮点边界反量化
```

乘加结果使用INT32累积，是因为许多INT8乘积相加后很容易超出INT8范围。例如，两个最大正INT8数相乘为 $127\times127=16129$，仅一个乘积就已超出INT8上界127。

设输入激活的缩放因子为 $s_x$，权重缩放因子为 $s_w$，去掉零点后的整数乘加结果为 $a_{int32}$，对应的浮点结果近似为：

\[
y_{float}\approx s_xs_w a_{int32}
\]

如果下一层需要使用缩放因子 $s_y$ 的INT8输入，推理内核还要把累加结果乘以 $s_xs_w/s_y$，再完成舍入和截断。这个步骤称为重新量化（Requantization）。

激活参数有两种获取时机：

- 动态激活量化在每次推理时统计当前激活范围，再计算本次使用的 `scale` 和 `zero-point`；
- 静态激活量化在训练完成后使用代表性数据运行一次校准流程，把得到的范围和量化参数写入模型，后续每次推理都复用这些固定参数。

这里先记住数据怎样变化。动态和静态方案的用途与代价在第5.4节具体介绍；静态方案怎样校准在第6章介绍。不同芯片还会使用定点乘法、移位和算子融合优化这条流程，具体实现留到对应部署章节。

## 5 量化方案的多个独立选择维度与框架配置

实际量化时需要同时确定多项方案。对称/非对称、per-tensor/per-channel、权重/激活、静态/动态、PTQ/QAT分别回答不同问题。每一组内部存在相对选项，各组之间可以组合，不能把所有术语放在同一个单选列表中。

例如，一个视觉CNN可以同时采用“PTQ + 权重和激活量化 + 静态激活量化 + 权重对称per-channel + 激活非对称per-tensor”。这是一套完整配置，其中每个词描述一个维度。

### 5.1 一次量化配置会组合多个独立选择维度

| 选择维度 | 典型相对选项 | 回答的问题 |
| --- | --- | --- |
| 数值范围怎样对应整数编码 | 对称 / 非对称 | 浮点0映射到哪里，正负范围怎样分配 |
| 一组参数覆盖多少数值 | per-tensor / per-channel | 整个张量共用参数，还是各通道分别使用参数 |
| 模型中的什么数值被量化 | 仅权重 / 权重与激活 | 只压缩固定参数，还是让中间计算也进入低位宽路径 |
| 激活参数何时计算 | 静态 / 动态 | 转换阶段固定参数，还是每次推理时计算参数 |
| 量化误差何时进入模型优化 | PTQ / QAT | 训练后直接转换，还是训练时模拟量化误差 |

因此，“选择了per-channel”不能说明模型是否量化激活，也不能说明模型使用PTQ还是QAT。检查一份量化模型时，要沿这些维度分别确认。

### 5.2 对称量化与非对称量化决定整数零点和范围分配

对称量化让浮点范围以0为中心，例如用 $[-2.0,2.0]$ 覆盖一个张量。对于常见的有符号对称INT8表示，可以使用 $[-127,127]$ 并令 `zero-point=0`：

\[
s=\frac{\max(|x_{\min}|,|x_{\max}|)}{127}
\]

它适合以0为中心分布的权重。非对称量化允许浮点范围两端距离0不同，并通过非零 `zero-point` 保证浮点0仍能准确表示。例如，ReLU后的激活集中在0以上，非对称范围可以把更多编码用于正数区域。

权重和激活可以使用不同选择。常见配置会让权重使用对称量化，让激活根据后端要求使用对称或非对称量化。

### 5.3 per-tensor与per-channel决定量化参数的共享范围

Per-tensor让整个张量共用一组 `scale` 和 `zero-point`。Per-channel为不同通道分别保存参数。以形状 `[C_out, C_in, kernel_h, kernel_w]` 的卷积权重为例，常见做法是为每个输出通道 `C_out` 单独计算一个 `scale`。

假设两个输出通道的权重范围分别为 $[-0.1,0.1]$ 和 $[-2,2]$。共用参数时必须覆盖 $[-2,2]$，第一个通道只能使用中央少量刻度；每通道量化可以让第一个通道用完整刻度覆盖 $[-0.1,0.1]$。

Per-channel通常有利于权重精度，但量化轴和算子实现必须得到目标后端支持。激活仍可以采用per-tensor，这与权重采用per-channel并不冲突。

### 5.4 权重量化、激活量化以及静态与动态激活量化

仅权重量化会压缩固定参数，运行时激活继续使用FP16、脑浮点16（Brain Floating Point 16，BF16）或FP32。权重与激活量化会让支持的卷积或矩阵乘法进入更完整的低位宽计算路径。

激活量化还要确定参数获取时机：

- 静态激活量化在转换阶段用校准数据确定 `scale` 和 `zero-point`，部署时重复使用固定参数；
- 动态激活量化在每次推理时根据当前激活计算参数，省去离线校准数据，但增加运行时统计与转换开销。

看到“W8A8”时，W8表示8位权重，A8表示8位激活；看到“W4A16”时，通常表示4位权重和16位激活。准确语义仍应以工具和硬件文档为准。

### 5.5 训练后量化（PTQ）与量化感知训练（QAT）

训练后量化（Post-Training Quantization，PTQ）在浮点模型训练完成后分析权重，并按所选方案处理激活。它不修改原训练过程，是部署已有模型时通常先尝试的流程。

量化感知训练（Quantization-Aware Training，QAT）在训练阶段插入伪量化操作，让前向计算模拟舍入和饱和误差，模型参数可以在训练中适应这些误差。PTQ精度无法满足要求时，再考虑QAT。

QAT与对称性、参数粒度、权重/激活位宽仍然可以组合。例如，QAT模型也可以使用对称per-channel权重和per-tensor激活。ONNX Runtime目前不负责QAT重训练；官方建议在原训练框架完成QAT后再导出ONNX，参见[ONNX Runtime量化方法选择](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html#method-selection)。

### 5.6 ONNX Runtime与RKNN Toolkit2如何组合前述量化方案

ONNX Runtime和RKNN Toolkit2不会从第5章的所有选项中只挑一个。一次模型转换会在每个维度上各确定一项，最后组合成完整方案。对于常见视觉模型，两套工具的对应关系如下：

| 第5章的选择维度 | ONNX Runtime | RKNN Toolkit2 |
| --- | --- | --- |
| PTQ或QAT | `quantize_static()`和`quantize_dynamic()`处理训练完成的浮点模型，属于PTQ；上游框架导出的QAT模型通常直接交给ONNX Runtime运行 | 浮点模型在构建时开启量化并提供数据集，属于PTQ；已经带有QAT量化关系的模型按QAT导入流程构建 |
| 量化权重还是同时量化激活 | 8位静态量化的常见配置是W8A8；另有面向特定算子的INT4/UINT4权重专用量化工具 | 视觉CNN部署常见W8A8；较新的Toolkit与部分芯片还可能提供W4A16、W4A8等格式，实际可选项由版本和目标芯片决定 |
| 静态还是动态激活量化 | 两种都可以选择。CNN通常使用静态激活量化并校准；RNN和Transformer更常尝试动态量化 | 常见ONNX转RKNN视觉流程使用静态激活量化，构建阶段读取校准数据，后续板端推理复用固定量化参数 |
| 对称还是非对称 | 当前`quantize_static()`默认让权重范围对称、激活范围保持非对称；两者都可通过配置修改。`QInt8`或`QUInt8`描述有符号或无符号类型，符号类型和对称性是两个不同属性 | `w8a8`只说明权重与激活的位宽，无法单独判断对称性。Toolkit会根据量化格式、目标平台和版本生成具体的`scale`与`zero-point`；RKNN运行时可查询最终张量的量化类型和参数 |
| per-tensor还是per-channel | `quantize_static()`当前默认`per_channel=False`，即权重使用per-tensor；设为`True`后，支持的权重可使用per-channel。激活通常按整个激活张量保存一组参数 | 视觉模型通常可以让卷积权重采用channel粒度，激活通常按张量统计范围。`quantized_method`等选项的名称、默认值和芯片支持情况需要以当前Toolkit API说明为准 |
| 校准方法 | 静态量化当前默认MinMax，也可以选择Entropy或Percentile | 常见版本提供普通范围统计以及MMSE等量化算法选项；支持项和默认值随Toolkit版本变化 |

把ONNX Runtime当前默认静态配置写成一行，就是“PTQ + W8A8 + 静态激活 + 对称权重 + 非对称激活 + 权重per-tensor + 激活per-tensor + MinMax校准”。其中QDQ是量化模型的图表示方式，属于输出模型怎样记录量化关系，不属于第5章前面几组数值方案。ONNX Runtime官方文档将CNN的静态量化、动态与静态的区别以及S8S8 QDQ推荐配置集中列出；具体接口默认值可查阅[ONNX Runtime量化文档](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)和[`quantize_static()`官方源码](https://github.com/microsoft/onnxruntime/blob/main/onnxruntime/python/tools/quantization/quantize.py)。

RKNN的常见YOLO路径可以先记成“PTQ + W8A8 + 静态激活量化 + 校准”。对称性、权重量化粒度和校准算法需要继续查看转换日志与当前版本的API说明。Rockchip会随Toolkit版本增加新的位宽和混合量化能力，参见[RKNN Toolkit2版本记录](https://github.com/airockchip/rknn-toolkit2/blob/master/rknn-toolkit2/doc/changelog-2.3.2.txt)。官方浮点模型示例通过构建阶段读取数据集完成PTQ；QAT示例要求关闭再次量化，参见[RKNN Toolkit2官方示例目录](https://github.com/airockchip/rknn-toolkit2/blob/master/rknn-toolkit2/examples/readme.txt)和[ResNet18 QAT示例](https://github.com/airockchip/rknn-toolkit2/tree/master/rknn-toolkit2/examples/pytorch/resnet18_qat)。

## 6 训练后静态量化的校准

校准主要出现在训练后量化（Post-Training Quantization，PTQ）并且采用静态激活量化的场景。两个条件需要同时满足：模型训练已经结束，后续推理还要固定使用预先计算的激活 `scale` 和 `zero-point`。

W8A8是常见情况，因为权重和激活都要映射到8位。其他静态激活格式也可能需要校准。仅权重量化可以直接读取固定权重；动态激活量化在每次推理时计算激活参数。这两类方案不需要为固定激活范围执行本章所说的离线校准。

### 6.1 YOLO静态W8A8量化为什么需要校准

YOLO等视觉CNN经常部署到提供INT8卷积内核的CPU、DSP或NPU，因此静态W8A8是一条常见路径。ONNX Runtime也把静态量化作为CNN的一般建议方向，参见[ONNX Runtime量化方法选择](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html#method-selection)。

YOLO的骨干网络、特征融合结构和检测头会产生随图像内容变化的中间激活。静态W8A8要求转换工具提前为这些激活确定固定范围，所以必须先用代表性图像运行浮点模型，观察各层大致分布，再生成量化参数。

例如，项目同时处理白天和夜间道路。校准集只有白天图像时，部分层记录的范围可能无法覆盖夜间灯光和噪声产生的响应。部署时超出范围的激活会饱和，随后可能改变检测置信度和边框回归结果。

### 6.2 静态激活量化的校准流程

校准发生在浮点模型训练完成之后、最终静态量化模型生成过程中：

```text
训练完成的浮点模型
→ 量化工具插入观察器或开启中间激活统计
→ 校准数据执行多次前向推理
→ 工具记录各层激活分布
→ 校准方法为各层选择范围
→ 计算scale和zero-point
→ 转换并保存静态量化模型
```

校准只执行前向推理，不更新权重，也不执行反向传播。标签不会参与激活范围统计，因此校准图片通常不需要检测框或类别标注。

以MinMax为例，工具记录观察到的最小值和最大值。Entropy和Percentile会采用不同规则处理分布与离群值。ONNX Runtime当前支持MinMax、Entropy和Percentile三种静态校准方法，参见[ONNX Runtime静态量化说明](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html#static-quantization)。

### 6.3 校准集需要什么数据

校准数据必须接近真实部署输入，并经过与部署一致的预处理。YOLO项目需要保持相同的图像解码、RGB或BGR顺序、letterbox、输入尺寸、像素缩放和归一化。

校准图片可以从训练集抽取，也可以从部署现场单独采集。选择标准是输入分布，训练标签不影响校准。固定道路摄像头可以按白天、黄昏、夜间、雨天和逆光分组；工业检测可以按产品类型、材质、缺陷尺度和曝光条件分组。

随机数组只能检查量化接口能否运行，无法代表真实激活。ONNX Runtime的QNN文档也明确提醒，随机输入很可能生成精度较差的量化模型，参见[QNN校准数据说明](https://onnxruntime.ai/docs/execution-providers/QNN-ExecutionProvider.html#quantization)。

### 6.4 校准图片通常需要多少张

量化框架没有适用于所有YOLO模型的固定图片数量。模型结构、业务分布、校准方法和后端实现都会改变需求。工程上可以把下面的数量作为首轮实验起点，不能当作框架硬性要求：

- 单摄像头、场景较固定的检测任务：先分层选择100～300张；
- 多摄像头、昼夜变化或背景复杂的任务：先选择300～1000张；
- 每个关键场景都要有样本，1000张高度重复的白天图片通常不如300张覆盖昼夜和目标尺度的图片有效。

数量是否足够应通过递增实验判断。例如，分别使用100张、300张和500张生成量化模型，并在同一评价集上比较mAP、原始输出误差和饱和情况。如果项目允许的mAP损失是0.5个百分点，可以把“连续两次增加校准数据后，mAP变化均小于0.1个百分点”作为一个停止条件。这个阈值来自项目容差，换项目后需要重新设定。

### 6.5 校准数据需要覆盖哪些范围

YOLO校准集通常需要覆盖：

- 白天、夜间、逆光和主要曝光条件；
- 简单背景与复杂纹理背景；
- 大、中、小目标及业务重点目标尺度；
- 无目标画面、稀疏目标和密集目标；
- 常见遮挡、运动模糊、噪声和压缩失真；
- 实际摄像头、分辨率和输入预处理路径。

覆盖范围应该按部署中出现的比例抽样，同时保留少量重要但低频的困难场景。校准集没有必要复制完整训练集；它需要让量化工具看到足以代表部署激活分布的输入。

### 6.6 校准集、训练集与评价集承担不同职责

| 数据集合 | 主要用途 | 是否需要标签 | 是否更新模型权重 |
| --- | --- | --- | --- |
| 训练集 | 通过反向传播学习模型参数 | 通常需要 | 是 |
| 校准集 | 前向运行并估计静态激活范围 | 通常不需要 | 否 |
| 评价集 | 比较浮点与量化模型的任务指标 | 需要 | 否 |

评价集应保持固定，用于公平比较不同校准规模和量化配置。反复依据评价结果挑选最有利的校准图片会让评价数据参与方案选择，因此最好另外保留最终测试数据。

离群值也会影响范围选择。例如，一个激活张量中99.9%的值位于 $[-1,1]$，少量值达到10。MinMax覆盖 $[-1,10]$ 时，常见区域的整数刻度会变粗；缩小范围又会让极端值饱和。校准方法解决的是这个范围取舍，最终仍要使用固定评价集验证。

## 7 量化误差的三个层级与从结果到数值的排查

量化误差从单个数值产生，经由一层中的大量计算汇集并向后传播，最后可能改变模型输出和任务指标。分析时要使用同源FP32模型作为基线，并保证两边输入与后处理一致。

### 7.1 单个数值、整层张量与最终指标的三层误差

量化误差可以分成三个层面：

1. **单个数值误差**：一个权重或激活经过量化和反量化后发生舍入或饱和。具体来源已在第3.4节解释。
2. **整层张量误差**：一层中大量权重和激活误差经过乘加、激活函数和分支融合汇集，使量化张量与FP32张量产生整体差异；该差异还会成为下一层输入。
3. **最终指标误差**：层级误差传播到模型输出，可能改变类别、置信度和边框，最终表现为精确率、召回率或平均精度均值（mean Average Precision，mAP）变化。

例如，两个类别的FP32得分为0.501和0.499。量化后变为0.498和0.502时，单次数值扰动已经改变最终类别。另一些张量虽然存在明显数值误差，但后处理结果保持不变，所以三个层面必须分别观察。

### 7.2 使用同源FP32模型建立比较基线

FP32基线用于回答“同一模型在量化前得到什么结果”。阶段4-3第3节已经介绍ONNX Runtime数值基线，本节直接沿用。

比较时固定以下条件：

- 同一份模型输入张量；
- 相同的输入名称、形状、数据类型和布局；
- 相同的输出节点对应关系；
- 相同的置信度阈值、NMS和坐标还原；
- 同一批带标注评价数据。

先确认PyTorch与FP32 ONNX结果一致，再比较FP32 ONNX与INT8 ONNX。这样可以把模型导出问题和量化误差分开。

### 7.3 先从最终任务指标和异常样本开始检查

排查从最上层开始。先在固定评价集上比较FP32与量化模型的mAP、精确率和召回率，再保存两边检测结果不同的图片。

需要观察的最终差异包括：

- 原本正确的目标是否漏检；
- 是否出现新的误检；
- 类别是否变化；
- 置信度是否集中下降；
- 小目标、夜间或某类场景是否特别容易退化；
- 边框位置和大小是否系统性偏移。

这一步确定“问题是否影响业务”以及“哪些输入最容易触发问题”。后面的逐层分析优先使用这些异常样本，不必一开始就导出所有图片的全部中间张量。

### 7.4 再逐层定位误差第一次明显增加的位置

最终结果确认退化后，再匹配FP32和量化模型中的对应输出与中间张量。比较形状相同的张量时，可以计算最大绝对误差：

\[
E_{max}=\max_i|y_i^{int8}-y_i^{fp32}|
\]

以及平均绝对误差：

\[
E_{mean}=\frac{1}{N}\sum_{i=1}^{N}|y_i^{int8}-y_i^{fp32}|
\]

其中 $N$ 是张量元素数量。还可以计算余弦相似度。各输出头的数值尺度由任务分支决定，应分别比较对应输出。

逐层按执行顺序观察这些指标，找到误差第一次明显增加的位置。ONNX Runtime当前在 `onnxruntime.quantization.qdq_loss_debug` 中提供权重匹配、扩展中间输出、收集激活和激活匹配接口，参见[ONNX Runtime量化调试文档](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html#quantization-debugging)。

### 7.5 最后逐点检查量化范围、离群值与饱和

定位到可疑层后，再检查具体数值：

1. 查看FP32张量的最小值、最大值和主要分布；
2. 读取该层实际使用的 `scale`、`zero-point` 和整数范围；
3. 统计多少数值落在量化上下界，判断是否出现大量饱和；
4. 检查权重各通道范围差异，判断per-tensor是否浪费刻度；
5. 找出误差最大的元素，并沿其输入、权重和输出关系检查误差来源。

处理方法应对应诊断结果：校准覆盖不足时补充数据；离群值影响范围时尝试其他校准方法；单层特别敏感时使用目标后端支持的per-channel或混合精度；算子未正确量化时检查后端支持和模型图。

### 7.6 在量化误差分析前排除输入输出链路错误

预处理和后处理错误也会造成巨大差异，必须先排除：

- RGB与BGR顺序不同；
- 一条路径漏做或重复执行像素归一化；
- NCHW与NHWC布局混用；
- 模型输入需要UINT8，调用代码仍传入未经转换的FP32；
- 多输出节点对应错误；
- letterbox比例、填充位置或坐标还原不同；
- 两条路径使用不同置信度阈值或NMS参数。

最稳妥的方法是把送入模型的最终张量保存为 `.npy`，让FP32与量化模型读取同一份数据。输入张量已经不同的情况下，后续误差不能归因于量化。

## 8 常见模型量化路径与ONNX静态量化Demo

实际项目很少只凭“模型用了INT8”这一句话决定量化方法。模型类型、部署平台和运行库共同决定工具链。目前可以先把常见流程分成两条路径：一条面向大语言模型的专用量化生态，另一条面向视觉模型和小模型的跨平台部署链路。

### 8.1 大语言模型通常使用专用量化格式与运行库

大语言模型通常不走视觉模型常见的“.pt转ONNX，再交给芯片工具”的路线。它们更常使用为Transformer和生成式推理设计的量化工具、文件格式与运行库。例如，llama.cpp可以把兼容模型转换为GGUF，再用`llama-quantize`生成不同位宽的量化版本；模型发布者也常直接提供已经量化的GGUF文件，使用者下载后交给llama.cpp加载运行。GPTQ、AWQ等量化模型同样需要匹配相应的加载库或推理框架。

这是一条常见工程路径，不代表大模型无法导出ONNX。这里的重点是：拿到一个带有“Q4”“Q8”或“GPTQ”“AWQ”标记的大模型时，需要先确认它的量化格式与运行库是否匹配，不能把它当成普通ONNX模型直接运行。llama.cpp支持的GGUF与量化入口可参见[llama.cpp官方仓库](https://github.com/ggml-org/llama.cpp)和[量化工具说明](https://github.com/ggml-org/llama.cpp/blob/master/tools/quantize/README.md)。

### 8.2 视觉模型与小模型通常先导出ONNX再适配平台

视觉模型和小模型的部署链路更常见下面这个过程：

```text
训练得到PyTorch模型或权重
        ↓
导出FP32 ONNX模型
        ↓
按照目标平台选择量化工具
        ↓
生成该运行时或芯片能够执行的量化模型
```

需要注意，`.pt`只是PyTorch常用的保存后缀。它可能保存完整模型，也可能只保存权重字典，因此实际导出ONNX时仍要使用与权重匹配的模型结构和导出代码。

- Linux x86 CPU使用ONNX Runtime部署时，可以直接用ONNX Runtime量化FP32 ONNX模型。
- Rockchip平台通常把FP32 ONNX交给RKNN Toolkit2，在构建RKNN模型时完成面向NPU的量化。具体接口、参数与板端验证放到后续RKNN专题阶段。
- PyTorch PT2E也能对接支持的后端完成部署；在本学习路线中，它主要适合在训练与导出阶段验证模型是否能够接受量化，以及提前观察精度变化，最终部署模型仍按目标平台的工具链生成。

因此，下面只保留一套完整的ONNX Runtime静态量化Demo。它最适合用来观察“准备校准数据、调用量化接口、生成量化模型”这条通用主线。

### 8.3 使用ONNX Runtime生成静态INT8 ONNX模型

这个Demo把`model_fp32.onnx`转换为`model_int8_qdq.onnx`。`calibration_tensors/`中的每个 `.npy` 文件保存一个已经完成部署预处理的FP32输入张量，例如YOLO常见的 `[1,3,640,640]`。

代码显式选择以下组合：

- 训练后静态量化；
- QDQ模型表示；
- INT8权重和INT8激活；
- 权重per-channel；
- MinMax校准。

这些参数共同构成一套方案。`quantize_static()`内部读取固定权重，同时反复调用`CalibrationDataReader.get_next()`取得校准输入、运行模型并统计激活，最后写出量化模型。

```python
from pathlib import Path
from typing import Iterator

import numpy as np
import onnx
import onnxruntime as ort
# 量化模块提供校准数据读取协议、量化方案枚举和静态量化入口。
from onnxruntime.quantization import (
    CalibrationDataReader,
    CalibrationMethod,
    QuantFormat,
    QuantType,
    quantize_static,
)


class NpyCalibrationDataReader(CalibrationDataReader):
    """按ONNX Runtime要求，逐个提供单输入模型的校准样本。

    model_path用于读取模型的真实输入名称和形状；data_directory中每个.npy
    文件保存一个已经完成部署预处理的FP32张量。get_next()每次返回一个
    “输入名称 -> NumPy张量”字典，全部样本读完后返回None。
    """

    def __init__(self, model_path: Path, data_directory: Path):
        # 这里创建会话只为读取输入元数据，不执行校准。校准推理由
        # quantize_static()在后面根据本Reader提供的数据统一完成。
        session = ort.InferenceSession(
            str(model_path), providers=["CPUExecutionProvider"]
        )
        inputs = session.get_inputs()

        # 这个教学Demo只处理单输入模型。多输入模型必须让get_next()返回
        # 包含全部输入名称的字典，直接继续会造成校准输入不完整。
        if len(inputs) != 1:
            raise ValueError(f"本Demo要求单输入模型，实际输入数为{len(inputs)}")

        # input_name是ONNX图中定义的真实输入名，后续作为输入字典的键。
        self.input_name = inputs[0].name

        # expected_shape记录模型声明的维度。固定维度保存为整数；动态batch、
        # 动态高宽等位置可能是字符串或None，后面的检查会保留这些动态位置。
        self.expected_shape = inputs[0].shape

        # files决定校准样本的读取顺序。排序可以让多次转换使用完全相同的顺序，
        # 便于比较不同量化配置；空目录直接报错，量化过程不会使用随机输入替代。
        self.files = sorted(data_directory.glob("*.npy"))
        if not self.files:
            raise FileNotFoundError(f"{data_directory}中没有.npy校准张量")

        # iterator保存当前读取进度并由当前Reader独占。None表示尚未开始读取，
        # rewind()会把它恢复为None，使量化工具可以从第一份样本重新开始。
        self.iterator: Iterator[dict[str, np.ndarray]] | None = None

    def _samples(self) -> Iterator[dict[str, np.ndarray]]:
        """加载并验证所有校准文件，每次产出一个模型输入字典。"""
        for file_path in self.files:
            # astype保证输入类型与浮点ONNX模型一致；copy=False允许原数组已经是
            # float32时复用其内存，类型不一致时NumPy仍会创建正确的新数组。
            tensor = np.load(file_path).astype(np.float32, copy=False)

            # 维度数量不同意味着NCHW/NHWC、batch维或预处理结果存在结构错误。
            # 此时立即拒绝该样本，避免用错误输入统计出无效激活范围。
            if tensor.ndim != len(self.expected_shape):
                raise ValueError(
                    f"{file_path.name}维度数为{tensor.ndim}，模型要求"
                    f"{len(self.expected_shape)}"
                )

            # 只比较模型中写死的整数维度。动态维度由当前样本决定，因此跳过；
            # 例如模型输入[batch,3,640,640]允许batch变化，后三维仍必须匹配。
            for actual, expected in zip(tensor.shape, self.expected_shape):
                if isinstance(expected, int) and actual != expected:
                    raise ValueError(
                        f"{file_path.name}形状{tensor.shape}与模型形状"
                        f"{self.expected_shape}不一致"
                    )

            # ONNX Runtime按名称绑定输入。这里产出的字典会被get_next()逐个
            # 交给量化器，每个张量触发一次浮点模型前向运行和中间激活统计。
            yield {self.input_name: tensor}

    def get_next(self):
        """返回下一份校准输入；返回None表示本轮数据已经全部读取。"""

        # 第一次调用时创建生成器，后续调用继续沿用其中保存的文件读取位置。
        if self.iterator is None:
            self.iterator = self._samples()
        try:
            return next(self.iterator)
        except StopIteration:
            # CalibrationDataReader协议使用None表示结束。量化器收到None后停止
            # 本轮校准，不会把“没有数据”当成一个有效模型输入。
            return None

    def rewind(self):
        """清除读取进度，让下一次get_next()重新从第一个文件开始。"""

        # 某些校准流程会多次遍历数据。旧生成器不再被引用，下一次get_next()
        # 会创建新生成器，并按self.files中相同的顺序重新读取全部样本。
        self.iterator = None


# 输入是训练完成并导出的FP32 ONNX；输出路径用于保存QDQ格式量化模型。
fp32_model = Path("model_fp32.onnx")
int8_model = Path("model_int8_qdq.onnx")

# 在创建推理会话前检查文件，可以把路径错误与模型解析错误区分开。
if not fp32_model.is_file():
    raise FileNotFoundError(f"缺少浮点模型：{fp32_model}")

# Reader持有校准文件列表和当前读取进度。quantize_static()会主动调用
# get_next()取得数据，脚本无需在外部手写校准循环。
calibration_reader = NpyCalibrationDataReader(
    fp32_model, Path("calibration_tensors")
)

# 量化器读取FP32模型与校准数据，并把下面显式指定的多项方案组合起来：
# 1. QDQ在原算子周围插入QuantizeLinear/DequantizeLinear，记录量化关系；
# 2. 激活和权重都使用有符号INT8，形成W8A8；
# 3. per_channel=True让支持的权重按通道分别计算量化参数；
# 4. MinMax根据校准期间观察到的各激活最小值、最大值确定静态范围。
# 调用成功后int8_model指向新生成的文件；失败时接口抛出异常，不应继续部署。
quantize_static(
    model_input=str(fp32_model),
    model_output=str(int8_model),
    calibration_data_reader=calibration_reader,
    quant_format=QuantFormat.QDQ,
    activation_type=QuantType.QInt8,
    weight_type=QuantType.QInt8,
    per_channel=True,
    calibrate_method=CalibrationMethod.MinMax,
)

# checker验证生成文件能否满足ONNX结构和算子定义。它不比较模型精度，
# 所以通过结构检查后仍要使用第7章的方法比较FP32与INT8输出及任务指标。
onnx.checker.check_model(onnx.load(int8_model))

# 文件大小只反映存储变化。量化是否真正加速还要在目标执行提供器上实测。
print(f"已生成：{int8_model}")
print(f"FP32大小：{fp32_model.stat().st_size / 1024 / 1024:.2f} MB")
print(f"INT8大小：{int8_model.stat().st_size / 1024 / 1024:.2f} MB")
```
