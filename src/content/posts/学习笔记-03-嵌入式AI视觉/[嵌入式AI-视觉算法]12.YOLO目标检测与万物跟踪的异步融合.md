# 阶段3-12 YOLO目标检测与万物跟踪的异步融合

## 1 YOLO检测结果在单目标跟踪中的两个用途

本章从检测线程已经返回某个历史帧的人车检测结果开始。YOLO网络结构、图像预处理、ONNX Runtime推理、输出解码和非极大值抑制（Non-Maximum Suppression，NMS）已经由Demo17负责，本章只处理这些结果怎样进入阶段3-11建立的万物跟踪器。

一个检测结果不能只画成新的显示框。当前Demo18把它用于两个层次：

```text
某个历史帧的YOLO结果
├─ 用途一：校正KCF的位置和尺度
│  ├─ 第一次发现人车：内部框切换为完整人车框
│  ├─ KCF可靠：对内部框做辅助校正
│  └─ KCF较弱：内部框直接采用高置信度YOLO框
│
└─ 用途二：校正KCF跟踪模型
   ├─ 根据校正框重新提取FHOG
   ├─ 训练新的模板特征与Alpha
   └─ 按学习率更新旧模型，或者完整重建模型
```

这两个用途存在固定顺序。程序先决定目标位于哪里、宽高是多少，再从对应帧的这个区域提取FHOG。YOLO图像块不会直接与旧FHOG矩阵相加；它先确定新的训练区域，随后仍使用阶段3-8至3-10的相关滤波训练流程产生模板特征与Alpha。

当前融合链中还存在第三种矩形：最终输出框。它由内部KCF框经过外部中心和尺寸平滑得到，只提供给画面显示或上层控制。它不参与下一帧搜索，也不参与FHOG训练。

因此本章需要持续区分以下对象：

| 对象 | 所属时刻 | 主要用途 |
|---|---|---|
| `submittedKcfRect` | YOLO送检历史帧 | 把检测结果和同一时刻的单目标轨迹关联 |
| YOLO检测框 | YOLO送检历史帧 | 提供该历史帧中目标的类别、位置和尺度 |
| `projectedYoloRect` | 当前帧 | 经过KCF运动补偿后的检测框 |
| `rawKcfRect` | 当前帧 | KCF内部真实框，决定下一帧搜索和模型状态 |
| `outputRect` | 当前帧 | 经过外部平滑的最终输出框 |
| `submittedFrame` | YOLO送检历史帧 | 在检测所属时刻重新提取FHOG训练样本 |

只融合 `outputRect` 会出现一种表面正常、内部仍然错误的状态：绿色显示框暂时落在目标上，KCF内部框和模板仍停留在旧目标或背景。下一帧KCF继续使用旧模型后，显示框会再次偏离。Demo18因此同时校正内部框和跟踪模型。

## 2 异步检测结果与当前视频帧的时间差

### 2.1 KCF逐帧运行与YOLO结果延迟返回

KCF每帧执行一次，YOLO在独立任务中运行。主线程提交第 $s$ 帧以后不会等待检测完成，而是继续对第 $s+1,s+2,\ldots$ 帧运行KCF。假设结果到第 $t$ 帧才返回，检测延迟为：

$$
L=t-s
$$

$s$ 是送检帧编号，$t$ 是当前帧编号，$L$ 的单位是视频帧。当前Demo18使用 `maximumYoloLagFrames=15`，只接受 $0\le L\le15$ 的结果。超过15帧的检测框仍然描述旧画面，把它直接写入当前状态可能将目标框拉回已经离开的地方。

为了在结果返回时还原送检时刻，后台任务必须一起保存以下数据。下面代码来自Demo18 `18_yolo_kcf_fusion_demo.cpp` 第189—198行，并补充了字段用途注释：

```cpp
/**
 * @brief 一个异步检测任务返回的完整结果。
 *
 * 检测框只描述frameIndex对应的历史帧。submittedKcfRect和submittedFrame
 * 必须与该帧一起保存，后续关联、延迟补偿和辅助训练都依赖同帧数据。
 */
struct AsyncYoloResult
{
    int frameIndex = 0;          // 送入YOLO的视频帧编号，计算延迟L=t-s时作为s。
    cv::Size frameSize;          // 历史帧原图尺寸，检查和限制检测框坐标。
    cv::Mat submittedFrame;      // 历史帧的独立副本，供同帧FHOG辅助训练使用。
    cv::Rect2f submittedKcfRect; // 送检时KCF内部框，供目标关联和运动补偿使用。

    // 该历史帧上的全部检测结果，每项包含类别、置信度和原图像素框。
    std::vector<yolo11_video_demo::Detection> detections;

    double inferenceMilliseconds = 0.0; // 本次后台检测耗时，单位为毫秒。
};
```

`submittedFrame` 必须复制图像数据。主线程下一次调用 `VideoCapture::read()` 时可能复用 `frame` 的内存；后台线程如果只保存一个浅拷贝视图，读取到的内容可能已经变成后续帧。当前代码在提交时调用 `frame.clone()`，使后台任务拥有独立图像数据。

Demo18没有建立待检测帧队列。`yoloSubmitInterval=1` 表示每帧都尝试提交；检测任务仍在运行时，新的请求立即计入 `busyDroppedFrames` 并丢弃。该策略让检测结果最多落后一次真实推理耗时，不会因为队列积压而持续增加延迟。

### 2.2 历史YOLO框向当前帧的投影

检测结果通过延迟检查后仍属于第 $s$ 帧。Demo18利用KCF在这段时间内测得的中心运动，把历史检测框平移到当前帧。

设：

- $\mathbf{c}^{s}_{k}$：送检时KCF框中心；
- $\mathbf{c}^{t}_{k}$：当前KCF框中心；
- $\mathbf{c}^{s}_{y}$：历史YOLO框中心；
- $\Delta\mathbf{c}_{k}$：KCF从第 $s$ 帧到第 $t$ 帧的中心位移。

先计算：

$$
\Delta\mathbf{c}_{k}=\mathbf{c}^{t}_{k}-\mathbf{c}^{s}_{k}
$$

再投影YOLO中心：

$$
\mathbf{c}^{t}_{y}=\mathbf{c}^{s}_{y}+\Delta\mathbf{c}_{k}
$$

投影框暂时保留历史YOLO框的宽高。当前代码只补偿平移；目标在检测延迟期间明显靠近、远离或旋转时，历史尺寸仍可能存在误差。

以下代码来自Demo18第416—434行：

```cpp
/**
 * @brief 把历史帧YOLO框投影到当前帧。
 * @param yoloResult 历史检测结果，包含送检时KCF框和帧号。
 * @param detection 与当前单目标关联成功的历史检测框。
 * @param currentKcfRect 当前帧KCF内部框。
 * @return 当前帧原图坐标中的YOLO投影框；宽高暂时沿用历史检测值。
 */
cv::Rect2f projectDetectionToCurrentFrame(
    const AsyncYoloResult& yoloResult,
    const yolo11_video_demo::Detection& detection,
    const cv::Rect2f& currentKcfRect) const
{
    // 两个KCF中心分别属于送检历史帧和当前帧，坐标单位都是原图像素。
    const cv::Point2f submittedCenter =
        rectCenter(yoloResult.submittedKcfRect);
    const cv::Point2f currentCenter = rectCenter(currentKcfRect);

    // kcfMotion表示检测推理期间KCF累计测得的目标平移量。
    const cv::Point2f kcfMotion(
        currentCenter.x - submittedCenter.x,
        currentCenter.y - submittedCenter.y);

    // 历史检测框左上角加上相同位移，宽高暂时保持检测时的数值。
    return cv::Rect2f(
        static_cast<float>(detection.box.x) + kcfMotion.x,
        static_cast<float>(detection.box.y) + kcfMotion.y,
        static_cast<float>(detection.box.width),
        static_cast<float>(detection.box.height));
}
```

这项补偿依赖一个前提：第 $s$ 帧到第 $t$ 帧之间KCF中心运动基本可信。如果KCF已经跟到树枝，$\Delta\mathbf{c}_{k}$ 也会带着错误。后面的置信度分支因此不能把“完成了投影”直接当作“当前框一定正确”。

## 3 YOLO检测结果与当前单目标的关联

### 3.1 类别、置信度和类别锁定

一个历史帧可能包含多个人和多辆车。融合模块先确定哪一个检测框属于当前单目标，再进行投影和模型更新。当前Demo18依次执行三层筛选：

1. 类别只接受COCO类别0 `person` 和类别2 `car`；
2. 置信度达到当前阶段要求；
3. 已锁定类别时，只接受与 `lockedClassId` 相同的类别。

第一次从任意区域切换为人车跟踪时使用 `aiSwitchConfidenceThreshold=0.50`。已经进入AI辅助跟踪以后，更新模型需要更可靠的检测结果，因此使用 `templateRefreshConfidenceThreshold=0.70`。

第一次关联成功后，默认 `lockClassAfterFirstMatch=true`。例如第一次关联对象是 `person`，`lockedClassId` 保存0；后续一辆车经过KCF附近时，即使置信度很高，也不会把当前人切换成车辆。类别锁定只能解决跨类别误切换，附近存在两个同类目标时仍需要空间关联。

### 3.2 KCF附近搜索区域与候选目标选择

空间关联使用检测所属历史帧的 `submittedKcfRect`。当前Demo18以其中心为中心，把宽、高分别扩大到原框的 `nearbySearchAreaScale=2.0` 倍：

$$
w_s=2w_k,\qquad h_s=2h_k
$$

其中 $w_k,h_k$ 是送检时KCF框宽高，$w_s,h_s$ 是关联搜索区域宽高。检测框必须与这个区域发生有效相交。这样用户只框住人头时，覆盖头部的完整人体框仍能进入候选；远处无关的人车不会因为全图置信度较高而接管当前轨迹。

候选不止一个时，程序计算KCF中心到检测矩形的最短距离：KCF中心位于检测框内部时距离为0；位于框外时，先把中心坐标限制到检测框边界，得到最近点，再计算欧氏距离。距离更小的候选优先；两个距离相差小于1像素时，置信度更高的候选优先。

以下代码来自Demo18第323—407行的核心关联逻辑：

```cpp
/**
 * @brief 在送检时KCF框附近选择与当前单目标最匹配的人或车。
 * @param yoloResult 历史帧检测结果以及同帧KCF框。
 * @param requiredConfidence 本次允许关联的最低检测置信度。
 * @return matched=false表示没有候选通过全部筛选；成功时同时返回检测项和距离。
 */
AssociationResult associateDetection(
    const AsyncYoloResult& yoloResult,
    float requiredConfidence) const
{
    AssociationResult best; // 默认matched=false，距离初始化为浮点最大值。

    const cv::Point2f kcfCenter = rectCenter(yoloResult.submittedKcfRect);
    const float searchWidth =
        yoloResult.submittedKcfRect.width * config.nearbySearchAreaScale;
    const float searchHeight =
        yoloResult.submittedKcfRect.height * config.nearbySearchAreaScale;

    // 关联区域和检测框都使用送检历史帧的原图像素坐标。
    const cv::Rect2f searchArea(
        kcfCenter.x - searchWidth * 0.5F,
        kcfCenter.y - searchHeight * 0.5F,
        searchWidth,
        searchHeight);

    for (const yolo11_video_demo::Detection& detection : yoloResult.detections)
    {
        // 当前学习工程只允许person和car进入单目标融合。
        if (detection.classId != 0 && detection.classId != 2)
        {
            continue;
        }

        // 锁定类别后拒绝其他类别，避免当前目标被附近的另一类物体替换。
        if (lockedClassId >= 0 && detection.classId != lockedClassId)
        {
            continue;
        }

        // 首次切换和后续刷新会传入不同阈值；未达标的框不参与空间排序。
        if (detection.confidence < requiredConfidence)
        {
            continue;
        }

        const cv::Rect2f detectionRect(
            static_cast<float>(detection.box.x),
            static_cast<float>(detection.box.y),
            static_cast<float>(detection.box.width),
            static_cast<float>(detection.box.height));

        // 没有交集表示检测目标离当前单目标轨迹过远，直接拒绝。
        const cv::Rect2f intersection = searchArea & detectionRect;
        if (intersection.width <= 0.0F || intersection.height <= 0.0F)
        {
            continue;
        }

        // 将KCF中心限制到检测框内，得到矩形上距离该中心最近的点。
        const float nearestX = std::clamp(
            kcfCenter.x, detectionRect.x, detectionRect.x + detectionRect.width);
        const float nearestY = std::clamp(
            kcfCenter.y, detectionRect.y, detectionRect.y + detectionRect.height);
        const float dx = nearestX - kcfCenter.x;
        const float dy = nearestY - kcfCenter.y;
        const float centerDistancePixels = std::sqrt(dx * dx + dy * dy);

        const bool closer = centerDistancePixels < best.centerDistancePixels;
        const bool sameDistanceHigherConfidence =
            std::abs(centerDistancePixels - best.centerDistancePixels) < 1.0F &&
            detection.confidence > best.detection.confidence;

        // 第一个合法候选直接保存；后续只接受更近或同距离下置信度更高的候选。
        if (!best.matched || closer || sameDistanceHigherConfidence)
        {
            best.matched = true;
            best.detection = detection;
            best.centerDistancePixels = centerDistancePixels;
        }
    }

    return best;
}
```

当前实现没有用IoU作为主要排序分数。原因是初始化KCF框可能只覆盖人头或车辆局部，完整YOLO框与小KCF框的IoU会很低；两者仍可能属于同一目标。搜索区域相交加中心到矩形的最短距离更适合“任意区域切换到完整人车框”的初始阶段。进入完整人车跟踪后，可以增加IoU作为辅助约束，但应先记录真实视频中的框尺度差异再设置阈值。

## 4 YOLO结果对KCF位置与尺度的校正

### 4.1 第一次发现人车时使用完整YOLO框

用户初始化时可以框选任意区域。第一次在附近关联到置信度不低于0.50的人或车后，Demo18设置 `firstAiSwitch=true`，并令 `forceFullYoloReset=true`。投影后的完整YOLO框会直接交给 `ProtectedFhogTracker::reinitialize()`。

这一步同时产生三个状态变化：

```text
targetRect_          → 完整YOLO投影框
FHOG模板与Alpha      → 在完整框处重新训练
aiTrackingActive     → true
```

若启用了类别锁定，程序同时把检测类别保存到 `lockedClassId`。下一帧KCF会围绕完整人车框提取搜索区域，用户最初选择的小框不再控制目标尺度。

### 4.2 KCF可靠时进行小幅位置和尺度校正

已经进入AI辅助跟踪且KCF状态为Reliable时，程序保留KCF逐帧运动能力，同时用YOLO修正长期偏差。修正先在检测所属的第 $s$ 帧计算。

历史融合框中心完全采用YOLO中心：

$$
\mathbf{c}^{s}_{f}=\mathbf{c}^{s}_{y}
$$

宽高使用权重 $\beta=0.2$：

$$
w^{s}_{f}=\beta w^{s}_{y}+(1-\beta)w^{s}_{k}
$$

$$
h^{s}_{f}=\beta h^{s}_{y}+(1-\beta)h^{s}_{k}
$$

这里的0.2只作用于宽高。中心采用完整YOLO中心，因为中心偏差会直接造成跟踪框落在目标旁边；宽高采用0.2/0.8融合，可以降低检测框逐帧尺寸波动对KCF搜索几何的冲击。

接着计算历史融合框相对历史KCF框的残差：

$$
\Delta\mathbf{c}=\mathbf{c}^{s}_{f}-\mathbf{c}^{s}_{k}
$$

$$
\Delta w=w^{s}_{f}-w^{s}_{k},\qquad
\Delta h=h^{s}_{f}-h^{s}_{k}
$$

把相同残差加到当前第 $t$ 帧KCF框：

$$
\mathbf{c}^{t}_{corrected}=\mathbf{c}^{t}_{k}+\Delta\mathbf{c}
$$

$$
w^{t}_{corrected}=w^{t}_{k}+\Delta w,\qquad
h^{t}_{corrected}=h^{t}_{k}+\Delta h
$$

这样得到的 `correctedCurrentRect` 才会写成当前KCF内部框。程序没有把第 $s$ 帧框原样写到第 $t$ 帧，因此目标正常运动时不会因异步结果退回旧位置。

### 4.3 KCF较弱时使用YOLO框硬重置

当前Demo18把KCF状态不等于Reliable视为 `kcfConfidenceLow`。当它同时遇到置信度不低于0.70的YOLO结果时，`forceFullYoloReset` 成立：

```text
KCF = Weak或Lost
+ YOLO置信度 ≥ 0.70
→ 使用投影到当前帧的完整YOLO框调用reinitialize()
```

硬重置不会继续使用0.2/0.8尺寸融合。此时KCF测得的位置和尺度已经缺乏可靠性，保留80%的KCF宽高会让新模型继续携带旧错误。重置成功后，内部框、FHOG模板和Alpha全部来自当前投影框。

硬重置还需要重置外部中心Kalman和尺寸稳定器。假设旧绿色框宽度为60像素，新的内部YOLO框宽度为120像素；尺寸平滑器仍保留旧状态时，绿色框会从60逐帧缓慢变到120，看起来像YOLO已经纠正但输出框仍然收拢不了。Demo18在硬重置后把两个平滑器立即放到新框状态。

### 4.4 YOLO漏检、关联失败和结果过期

下面四种情况都不会修改KCF内部框和模型：

- 历史帧没有检测到人或车；
- 检测置信度没有达到当前阈值；
- 检测框没有通过类别或空间关联；
- 结果延迟超过15帧。

此时Demo18继续使用本帧已经执行完成的 `ProtectedFhogTracker::update()` 结果。遮挡期间YOLO漏检不会立刻改变跟踪方式；KCF仍先按阶段3-10的Peak、PSR和连续Weak/Lost条件运行。

当前Demo18测试入口设置 `enableRecapture=true`，因此连续Lost达到3帧或连续Weak达到5帧以后，Demo16内部还会尝试灰度健康模板的局部匹配，匹配阈值为0.60。这个恢复分支由KCF置信度计数触发，与“本帧YOLO没有检测框”不是同一个条件。局部模板匹配失败后，系统继续保留受保护的KCF状态，等待后续KCF恢复或高置信度YOLO结果重新出现。

## 5 YOLO结果对KCF模板与模型的校正

### 5.1 校正后的目标框怎样成为训练区域

框校正解决“下一帧从哪里继续搜索”，模型校正解决“下一帧拿什么外观特征去寻找”。只把 `targetRect_` 改成YOLO框时，历史FHOG模板仍可能描述旧局部区域、树枝或遮挡物。因此每次允许YOLO进入内部状态时，程序都要确定一个与图像时刻匹配的训练区域。

可靠辅助路径使用：

```text
submittedFrame（第s帧图像）
+ historicalFusedRect（第s帧融合框）
→ 提取同帧FHOG训练样本
```

硬重置路径使用：

```text
currentFrame（第t帧图像）
+ projectedYoloRect（投影到第t帧的完整框）
→ 完整重建当前KCF
```

历史检测框不能直接用于裁剪当前帧。检测框描述第 $s$ 帧，当前图像属于第 $t$ 帧；目标已经运动后，两者组合可能截到背景。Demo18因此保存 `submittedFrame`，让可靠辅助训练使用严格同帧的图像和矩形。

### 5.2 新训练区域怎样生成模板特征和Alpha

`trainWithAuxiliary()`接收四个关键输入：历史图像、历史训练框、训练后当前跟踪框和学习率。它在历史训练框处提取FHOG，训练出一份临时相关滤波模型，再将临时模型融合进旧模型：

$$
X_{new}=(1-\eta)X_{old}+\eta X_{sample}
$$

$$
\widehat{\alpha}_{new}
=(1-\eta)\widehat{\alpha}_{old}
+\eta\widehat{\alpha}_{sample}
$$

$X$ 是FHOG模板特征，$\widehat{\alpha}$ 是Alpha频谱，$\eta$ 是学习率。`FusionConfig`中的 `kcfConfig.learningRate` 默认继承Demo16的0.005；当前Demo18测试入口第1054行把它显式设为0.01。文章描述当前视频Demo行为时采用0.01，单独构造默认配置对象时仍是0.005。

下面代码来自Demo16 `16_confidence_recapture_demo.cpp` 第1544—1604行核心部分：

```cpp
/**
 * @brief 使用一张辅助样本更新KCF模型，并把内部框移动到补偿后的当前位置。
 * @param frame 与auxiliaryRect属于同一时刻的BGR或灰度图像。
 * @param auxiliaryRect 在frame中提取FHOG的训练框，单位为原图像素。
 * @param trackingRectAfterTraining 训练完成后写入的当前内部框。
 * @param learningRate 新样本模型的权重，合法范围为[0,1]。
 * @return 模型和内部状态全部更新成功时返回true；失败时返回false。
 */
bool ProtectedFhogTracker::trainWithAuxiliary(
    const cv::Mat& frame,
    const cv::Rect2f& auxiliaryRect,
    const cv::Rect2f& trackingRectAfterTraining,
    float learningRate)
{
    // 输入无效时保持旧模型和旧内部框，调用者不能把本次辅助标记为成功。
    if (!initialized_ || frame.empty() || frame.size() != frameSize_ ||
        frame.depth() != CV_8U ||
        (frame.channels() != 1 && frame.channels() != 3) ||
        !std::isfinite(learningRate) || learningRate < 0.0F || learningRate > 1.0F)
    {
        return false;
    }

    cv::Rect2f legalRect;         // 同帧图像中的实际FHOG训练框。
    cv::Rect2f legalTrackingRect; // 训练成功后写入的当前帧内部框。

    try
    {
        // 两个框可能来自不同帧，但都先限制为各自原图中的合法矩形。
        legalRect = legalizeRect(auxiliaryRect, frame.size());
        legalTrackingRect = legalizeRect(
            trackingRectAfterTraining, frame.size());

        // 在辅助训练框周围建立搜索区，得到固定24×24×31 FHOG样本。
        const cc_fhog_demo::CcFhogResult feature =
            featureExtractor_.extractFromFrame(frame, legalRect);
        const auto& trackerConfig = config_.scaleTrackerConfig.trackerConfig;

        // 使用辅助FHOG重新训练一份样本模板和Alpha，旧model_暂时保持不变。
        const filter_train_demo::CorrelationFilterModel sampleModel =
            filter_train_demo::trainCorrelationFilter(
                feature.feature,
                trackerConfig.labelSigma,
                trackerConfig.kernelSigma,
                trackerConfig.regularization);

        // 非有限值会污染后续每一帧频域计算，因此拒绝整次模型更新。
        if (sampleModel.templateFeature.empty() ||
            sampleModel.alphaSpectrum.empty() ||
            !cv::checkRange(sampleModel.templateFeature) ||
            !cv::checkRange(sampleModel.alphaSpectrum))
        {
            return false;
        }

        // 同时融合模板特征和Alpha，保证模型的两个组成部分来自同一时间权重。
        online_update_demo::interpolateTrackingModel(
            model_, sampleModel, learningRate);
    }
    catch (const std::exception&)
    {
        return false; // 特征提取或训练失败时保留原模型。
    }

    // 保存原图训练区域，供调试窗口观察KCF最近实际学习了哪块图像。
    cv::Mat trainingImage = extractTargetImage(frame, legalRect);
    if (trainingImage.empty())
    {
        return false;
    }

    // 模型来自历史同帧样本；下一帧搜索必须从已经补偿到当前时刻的框继续。
    targetRect_ = legalTrackingRect;
    lastReliableRect_ = legalTrackingRect;
    modelImageTemplate_ = trainingImage.clone();

    // 高置信度AI关联样本同时成为新的健康模板，并清空相关累计计数。
    healthyTemplate_ = std::move(trainingImage);
    healthyTemplateStableCount_ = 0;
    framesSinceHealthyTemplateRefresh_ = 0;
    modelUpdateEligibleFrameCount_ = 0;
    return true;
}
```

这里有一个实现边界需要注意：`legalTrackingRect`在当前函数中按 `frame.size()` 合法化。Demo18要求视频各帧尺寸一致，因此历史帧与当前帧边界相同；如果工程允许动态分辨率，函数还需要分别接收训练帧尺寸和当前帧尺寸。

### 5.3 首次切换时的完整模型重建

首次切换调用 `reinitialize(currentFrame, projectedYoloRect)`。`reinitialize()`内部调用 `rebuildModel()`，在完整YOLO投影框处重新建立搜索区域、提取FHOG并训练模板和Alpha。旧KCF模型被完整替换，学习率不参与这次重建。

该路径的作用是改变跟踪对象的定义。例如用户最初只框住人的头部，初始KCF学到的是头部和周围背景；YOLO返回完整人体框后，重建模型使“当前要跟踪的区域”变为完整人体。只把框放大而保留头部模型，会造成框看似覆盖全身，响应仍主要由头部特征决定。

### 5.4 KCF可靠时的辅助模型更新

KCF可靠且检测关联成功时，Demo18调用：

```cpp
return kcfTracker.trainWithAuxiliary(
    yoloResult.submittedFrame, // 第s帧图像，与历史检测框严格同帧。
    historicalFusedRect,       // 第s帧的YOLO中心与0.2/0.8融合尺寸。
    correctedCurrentRect,      // 残差补偿到第t帧后的当前内部框。
    config.kcfConfig.learningRate); // Demo18测试入口设置为0.01。
```

这个调用把模型学习和当前位置更新放在一次操作中：FHOG样本来自检测真实所属的历史帧，下一帧搜索中心则采用补偿后的当前框。模板与Alpha按小学习率更新，所以一次检测结果不会完全覆盖KCF已经学习的外观。

这也回答了“是否只有第一次使用YOLO模板”的问题。第一次切换会完整重建；后续置信度不低于0.70且关联成功的检测结果仍会进入 `trainWithAuxiliary()`，持续校正FHOG模板和Alpha。

### 5.5 KCF较弱时的模型硬重置

KCF为Weak或Lost时，历史模型可能已经对当前目标缺乏区分能力。高置信度YOLO结果此时调用：

```cpp
// projectedYoloRect已经利用KCF累计位移投影到当前帧，并限制在画面范围内。
if (forceFullYoloReset)
{
    // reinitialize()在当前图像和完整框处重建FHOG模板、Alpha及内部框。
    return kcfTracker.reinitialize(currentFrame, projectedYoloRect);
}
```

该路径不会把旧模板按0.99权重保留，因为旧模型已经处于低置信度状态。重建成功以后，`result.yoloHardReset=true`，并同步重置输出框平滑状态。若重建失败，`kcfCorrected`保持false，旧KCF状态继续保留，调用者不能仅凭“YOLO有关联框”就宣告恢复成功。

## 6 内部KCF框、YOLO框与最终输出框

### 6.1 三种框的作用和数据流向

Demo18调试画面中的三种框对应不同层次：

| 颜色 | 结果字段 | 含义 | 是否参与下一帧跟踪 |
|---|---|---|---|
| 蓝色 | `rawKcfRect` | YOLO校正完成后的KCF内部真实框 | 是 |
| 紫色 | `projectedYoloRect` | 历史YOLO框投影到当前帧后的参考框 | 否 |
| 绿色 | `outputRect` | 内部框经过中心和尺寸平滑后的最终输出 | 否 |

紫色框与蓝色框大小不同不能单独作为融合失败的判断依据。KCF可靠时，蓝色框宽高严格采用0.2 YOLO和0.8同帧KCF融合，紫色框保留完整YOLO尺寸；只要同帧KCF尺寸与YOLO尺寸不相等，两者就会产生尺寸差。第一次切换或低置信度硬重置成功时，内部框直接使用完整投影框，此时蓝色与紫色应基本重合。

绿色框和蓝色框短时间不同来自外部平滑。蓝色框已经影响下一帧搜索和模型训练，绿色框只用于输出。如果观察算法是否真正接受了YOLO校正，应优先查看蓝色内部框和右侧的最新训练图像；只看绿色框会把平滑滞后误认为KCF没有更新。

### 6.2 输出框的中心与尺寸平滑

Demo18分别处理中心和宽高：

- 中心Kalman状态为 $[x,y,v_x,v_y]^T$，测量为内部KCF中心 $[x,y]^T$；
- `BoxSizeStabilizer`接收内部宽高，输出稳定宽高；
- 两项结果组合成 `outputRect`，随后限制到当前画面。

Kalman滤波包含速度状态，可以根据前几帧运动预测下一中心，再用本帧KCF中心修正。测量噪声越大，输出越平稳，对当前测量的跟随也越慢。当前Demo18配置中位置过程噪声为0.05、速度过程噪声为0.50、测量噪声为2.0。

以下代码来自Demo18第829—857行：

```cpp
/**
 * 使用KCF内部真实框生成外部平滑输出。
 * stableSize和stableCenter都只用于outputRect，不写回kcfTracker。
 */
result.rawKcfRect = impl_->kcfTracker.currentRect();

// 尺寸稳定器独立处理宽高，输入与输出单位都是当前原图像素。
const cv::Size2f stableSize = impl_->outputSizeStabilizer.update(
    cv::Size2f(result.rawKcfRect.width, result.rawKcfRect.height));

// 中心Kalman先预测[x,y,vx,vy]，再用当前内部中心修正位置和速度。
const cv::Point2f internalCenter = rectCenter(result.rawKcfRect);
const cv::Point2f stableCenter =
    impl_->updateOutputCenterFilter(internalCenter);

// 把平滑中心和宽高重新组合为显示框，并限制到当前画面范围。
result.outputRect = legalizeRect(
    cv::Rect2f(
        stableCenter.x - stableSize.width * 0.5F,
        stableCenter.y - stableSize.height * 0.5F,
        stableSize.width,
        stableSize.height),
    frame.size());

if (impl_->yoloFusionEnabled)
{
    // 新任务保存内部KCF框；绿色outputRect带有滞后，不能用于历史帧关联。
    impl_->submitYoloIfPossible(frame, frameIndex, result.rawKcfRect);
}
```

普通可靠跟踪中，平滑器逐帧工作以降低高频抖动。首次切换或硬重置使内部框发生跳变时，Demo18调用 `reset()` 把平滑中心和尺寸立即设置到新框。该操作避免旧平滑状态制造长时间滞后。

## 7 Demo18的完整逐帧融合流程与代码展示

Demo18的 `YoloKcfFusionTracker::update()`遵循一条固定主路径：先让KCF完成当前帧，再非阻塞消费历史检测结果，随后输出平滑框，最后尝试提交当前帧检测。检测线程不会阻塞每帧KCF路径。

```text
当前第t帧frame
→ ProtectedFhogTracker::update(frame)
→ 得到当前rawKcfRect、Peak、PSR和置信度
→ wait_for(0ms)检查历史检测任务
   ├─ 尚未完成：本帧继续使用KCF
   └─ 已完成
      → 计算yoloLagFrames=t-s
      → 延迟合法后在第s帧关联person/car
      → 将历史YOLO框投影到第t帧
      → 根据KCF置信度选择辅助训练或硬重置
→ 从最终内部KCF框生成外部平滑outputRect
→ YOLO开关打开时尝试提交第t帧
   ├─ 未到提交间隔：跳过
   ├─ 后台仍繁忙：丢弃本次请求
   └─ 后台空闲：复制frame并启动异步任务
```

以下代码依据Demo18第685—881行整理，只保留融合主流程。省略的输入检查、耗时统计和调试字段不会改变决策顺序：

```cpp
/**
 * @brief 处理当前视频帧，并把已经完成的历史检测结果融合进单目标跟踪器。
 * @param frame 当前第frameIndex帧，必须与初始化视频尺寸一致。
 * @param frameIndex 单调递增且大于0的视频帧编号。
 * @return 当前KCF结果、检测融合状态和最终输出框。
 *
 * 主线程依次调用本函数；后台任务只产生AsyncYoloResult，不直接修改KCF。
 */
FusionResult YoloKcfFusionTracker::update(
    const cv::Mat& frame,
    int frameIndex)
{
    FusionResult result;
    result.yoloFusionEnabled = impl_->yoloFusionEnabled;

    // 第一步：KCF每帧运行。YOLO是否繁忙不会阻塞这条实时路径。
    result.kcfResult = impl_->kcfTracker.update(frame);
    result.rawKcfRect = impl_->kcfTracker.currentRect();

    // 第二步：wait_for(0ms)只查询状态，不等待后台检测完成。
    // yoloReady=false时本帧跳过整个融合分支，前面得到的KCF状态保持不变。
    const bool yoloReady =
        impl_->yoloRunning &&
        impl_->yoloFuture.wait_for(std::chrono::milliseconds(0)) ==
            std::future_status::ready;

    if (yoloReady)
    {
        // get()把后台结果移动到主线程；此后只有主线程会修改KCF状态。
        Impl::AsyncYoloResult yoloResult = impl_->yoloFuture.get();
        impl_->yoloRunning = false;

        // 关闭融合开关期间完成的旧任务只回收结果，不允许修改框或模板。
        const bool discardResult =
            !impl_->yoloFusionEnabled || impl_->discardPendingYoloResult;
        impl_->discardPendingYoloResult = false;

        // discardResult=true时只回收future，不允许旧任务修改框、模板或类别锁。
        if (!discardResult)
        {
            result.yoloResultArrived = true;
            result.yoloLagFrames = frameIndex - yoloResult.frameIndex;

            // 只消费属于过去或当前、且延迟未超过配置上限的结果。
            const bool lagAccepted =
                result.yoloLagFrames >= 0 &&
                result.yoloLagFrames <= impl_->config.maximumYoloLagFrames;

            // 延迟不合法时保留本帧KCF结果，并直接放弃这份历史检测数据。
            if (lagAccepted)
            {
                // 首次切换采用0.50；已有AI模板刷新采用更严格的0.70。
                const float requiredConfidence = impl_->aiTrackingActive
                    ? impl_->config.templateRefreshConfidenceThreshold
                    : impl_->config.aiSwitchConfidenceThreshold;

                const Impl::AssociationResult association =
                    impl_->associateDetection(yoloResult, requiredConfidence);

                // 没有关联候选时不执行投影、框校正和模型训练。
                if (association.matched)
                {
                    result.yoloMatched = true;
                    result.yoloConfidence = association.detection.confidence;

                    const bool firstAiSwitch = !impl_->aiTrackingActive;
                    const bool kcfConfidenceLow =
                        result.kcfResult.confidence.level !=
                        confidence_recapture_demo::ConfidenceLevel::Reliable;
                    const bool highConfidenceYolo =
                        association.detection.confidence >=
                        impl_->config.templateRefreshConfidenceThreshold;

                    // 首次切换或“低置信度KCF+高置信度YOLO”执行完整重建。
                    const bool forceFullYoloReset =
                        firstAiSwitch || (kcfConfidenceLow && highConfidenceYolo);

                    // 该函数同时完成框校正和模型校正：
                    // 完整重建使用当前投影框；可靠辅助使用历史同帧融合框训练。
                    // 返回false表示重建或辅助训练失败；KCF原有模型继续有效。
                    if (impl_->replaceKcfTemplateWithYolo(
                            frame,
                            yoloResult,
                            association.detection,
                            forceFullYoloReset,
                            result.projectedYoloRect))
                    {
                        result.kcfCorrected = true;
                        result.rawKcfRect = impl_->kcfTracker.currentRect();

                        if (forceFullYoloReset)
                        {
                            // 内部框发生完整跳转后，清除旧输出平滑状态产生的拖尾。
                            impl_->outputSizeStabilizer.reset(cv::Size2f(
                                result.rawKcfRect.width,
                                result.rawKcfRect.height));
                            impl_->resetOutputCenterFilter(
                                rectCenter(result.rawKcfRect));
                            result.yoloHardReset = true;
                        }

                        if (firstAiSwitch)
                        {
                            // 首次完整切换成功后才进入AI辅助状态并锁定类别。
                            impl_->aiTrackingActive = true;
                            result.switchedToYoloTemplate = true;

                            if (impl_->config.lockClassAfterFirstMatch)
                            {
                                impl_->lockedClassId = association.detection.classId;
                            }
                        }
                        else
                        {
                            result.yoloTemplateRefreshed = true;
                        }
                    }
                }
            }
        }
    }

    // 第三步：从最终KCF内部框生成只供输出的平滑矩形。
    result.rawKcfRect = impl_->kcfTracker.currentRect();
    const cv::Size2f stableSize = impl_->outputSizeStabilizer.update(
        cv::Size2f(result.rawKcfRect.width, result.rawKcfRect.height));
    const cv::Point2f stableCenter =
        impl_->updateOutputCenterFilter(rectCenter(result.rawKcfRect));
    result.outputRect = legalizeRect(
        cv::Rect2f(
            stableCenter.x - stableSize.width * 0.5F,
            stableCenter.y - stableSize.height * 0.5F,
            stableSize.width,
            stableSize.height),
        frame.size());

    // 第四步：消费旧结果后再提交当前帧，使刚结束的任务立即释放检测槽位。
    if (impl_->yoloFusionEnabled)
    {
        impl_->submitYoloIfPossible(frame, frameIndex, result.rawKcfRect);
    }

    result.yoloBusy = impl_->yoloRunning;
    result.aiTrackingActive = impl_->aiTrackingActive;
    result.lockedClassId = impl_->lockedClassId;

    // 原KCF有效或本帧YOLO成功重建，任一条件成立都可输出融合结果。
    result.valid = result.kcfResult.valid || result.kcfCorrected;
    return result;
}
```

运行Demo18时，右侧字段可以用来区分流程真正执行到了哪一步：`arrived`表示历史任务已经返回，`matched`表示找到关联目标，`switch`表示首次切换完整模板，`refresh`表示后续辅助训练，`hard`表示低置信度下完整重建。只有 `kcfCorrected=true` 才表示检测结果已经实际改变KCF内部状态。

调试框用于观察不同层次的结果：蓝色框检查内部KCF状态，紫色框检查延迟投影后的YOLO参考，绿色框检查上层最终输出。关闭调试框时只保留绿色输出；按 `Y` 关闭YOLO融合后，程序停止提交新检测任务，已在运行的任务自然完成并被丢弃，KCF继续按阶段3-11的纯视觉流程逐帧运行。
