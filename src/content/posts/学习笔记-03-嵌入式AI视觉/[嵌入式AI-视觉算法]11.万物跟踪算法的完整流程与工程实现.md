# 阶段3-11 万物跟踪算法的完整流程与工程实现

阶段3-8已经说明相关滤波怎样训练模型、产生响应图并从峰值求出位移，阶段3-9完成了跟踪使用的FHOG特征，阶段3-10又加入在线更新、尺度估计、置信度保护和局部重捕获。本章不再展开这些模块的内部公式，只解决一个整体问题：第一帧完成框选后，一张新的视频帧怎样依次经过这些模块，并最终变成一个可以接受、冻结或恢复的目标框。

完整主线可以先压缩为：

```text
第一帧用户框
→ 建立初始相关滤波模型和健康模板

后续每一帧
→ 原尺度相关滤波检测
→ 得到候选位置、Peak和PSR
→ 判断候选位置是否可信
   ├─ 可信：允许位置、尺度和受保护的模型更新
   ├─ 暂时较弱：允许短时位置移动，冻结高风险操作
   └─ 持续较弱或丢失：拒绝候选位置，尝试局部重捕获
→ 保存内部状态
→ 向外部返回目标框和本帧决策
```

## 1 万物跟踪器的整体输入、状态与输出

“万物跟踪”表示跟踪器不要求用户框内一定是人或车辆。用户在第一帧给出任意矩形区域，跟踪器根据这一区域建立外观模型，后续依靠图像特征连续定位。因此，它的最小输入只有两类：

- 初始化输入：第一帧 `firstFrame` 和用户框 `initialRect`；
- 更新输入：下一帧 `frame`。

跟踪器需要把上一帧结果保存到下一帧继续使用。当前Demo中的主要内部状态为：

| 内部状态 | 保存的内容 | 下一步由谁使用 |
|---|---|---|
| `targetRect_` | 当前内部目标框，单位为原图像素 | 下一帧以它为中心提取搜索区域 |
| `model_` | FHOG模板特征和Alpha频谱 | `detectTarget()`用它计算本帧响应图 |
| `lastReliableRect_` | 最近一次允许模型更新的可靠位置 | 丢失后以它为中心建立局部重捕获区域 |
| `healthyTemplate_` | 高置信度帧保存的原图目标ROI | `matchHealthyTemplateLocally()`用于恢复目标 |
| `modelUpdateEligibleFrameCount_` | 连续允许模型更新的帧数 | 决定是否到达在线更新间隔 |
| Weak/Lost计数 | 连续较弱或丢失的帧数 | 决定是否停止沿弱响应移动并启动重捕获 |

每帧检测还会产生一个 `proposedRect`。它表示相关滤波根据响应峰值提出的新位置，此时尚未写入 `targetRect_`。程序先检查Peak、PSR和连续低置信度次数，再决定接受还是拒绝这个候选框。这个暂存步骤很重要；如果检测一结束就覆盖 `targetRect_`，Lost状态已经来不及保留上一帧位置。

跟踪器最终返回的结果除了目标框，还应包含Peak、PSR、响应图、是否接受位置、是否改变尺度、是否更新模型以及是否重捕获。这些字段让上层知道框是怎样得到的，也便于判断“当前正在正常FHOG跟踪”还是“已经进入模板匹配恢复”。

## 2 第一帧的跟踪器初始化流程

初始化的作用是把“原图中的一个用户框”转换成后续每帧可以重复使用的相关滤波模型。实际顺序为：

```text
firstFrame + initialRect
→ 将目标框限制为合法尺寸和画面内位置
→ 以目标框中心建立更大的正方形搜索区域
→ 画面外部分进行边界填充
→ 将搜索图缩放到FHOG固定输入尺寸
→ 提取24×24×31 FHOG并乘Hann窗
→ 生成高斯期望响应并训练初始模型
→ 保存targetRect_和lastReliableRect_
→ 从原图复制初始healthyTemplate_
→ 清空Weak、Lost、模型更新和模板刷新计数器
```

这里会出现用户框、搜索区域和FHOG固定输入三种尺寸。用户框表示要跟踪的对象范围；搜索区域比用户框大，为下一帧运动预留空间；搜索区域最终统一缩放到固定模型尺寸，使FHOG特征和相关滤波模型始终保持固定形状。

当前代码的主要调用关系为：

```text
ProtectedFhogTracker::initialize()
└─ rebuildModel()
   ├─ limitRectSize()
   ├─ clampRectToFrame()
   ├─ CcFhogExtractor::extractFromFrame()
   └─ trainCorrelationFilter()
```

`extractFromFrame()`内部复用了Demo05的搜索区域提取和Demo12的FHOG生成。`trainCorrelationFilter()`内部复用了高斯标签、高斯核相关和频域复数运算。初始化成功后，调用者不再需要保存用户框；跟踪器通过 `targetRect_` 和 `model_` 接续后面的每一帧。

## 3 后续每帧的基础位置检测流程

每帧更新先执行一次原尺度检测。这里的“原尺度”指目标框宽高暂时沿用上一帧，先只求目标中心移动了多少。执行顺序为：

```text
保存previousRect = targetRect_
→ 以previousRect为中心提取当前搜索区域和FHOG
→ detectTarget()生成响应图
→ 得到Peak、PSR和亚Cell峰值位置
→ 将Cell位移换算成搜索图像素位移
→ 再换算成原图像素位移
→ previousRect加上原图位移
→ 得到normalProposedRect
```

这一阶段使用的函数分别来自前面的Demo：

```text
CcFhogExtractor::extractFromFrame()
→ 输出当前FHOG和搜索区域缩放关系

response_detection_demo::detectTarget()
→ 输出响应图、Peak、PSR和featureDisplacement

response_detection_demo::featureDisplacementToImage()
→ 把Cell位移恢复成原图像素位移

scale_tracker_demo::clampRectToFrame()
→ 保持候选框宽高并移动其左上角，使其完整位于画面内
```

位移换算链为：

```text
响应图峰值相对中心的偏移
→ featureDisplacement，单位为FHOG Cell
→ 乘Cell边长，得到固定搜索图中的像素位移
→ 乘搜索图到原图的缩放比例
→ imageDisplacement，单位为原图像素
```

例如，目标在响应图上向右移动了2.5个Cell，FHOG的Cell边长为4个固定搜索图像素，那么固定搜索图位移为10像素。若当前固定搜索图的1像素对应原图2像素，最终原图位移就是20像素。程序把这20像素加到 `previousRect.x` 上，形成 `normalProposedRect`。

原尺度检测完成后，内部 `targetRect_` 仍然保存上一帧框。下一步必须先让置信度模块判断候选位置能否进入内部状态。

## 4 置信度判断与流程分支

Demo16使用原尺度响应的Peak和PSR调用 `ConfidenceGuard::evaluate()`。Peak划分主要位置区间，PSR进一步判断主峰是否足够突出。该函数不会直接修改目标框或模型，只返回一组操作许可。

当前配置的判断关系为：

| 条件 | 状态 | 位置 | 尺度 | 模型 | 后续处理 |
|---|---|---|---|---|---|
| `Peak > 0.50`且`PSR > 7.0` | Reliable | 接受 | 允许 | 允许 | 进入正常更新路径 |
| `Peak > 0.50`但`PSR <= 7.0` | Weak | 短时接受 | 冻结 | 冻结 | 累加Weak次数 |
| `0.15 < Peak <= 0.50` | Weak | 短时接受 | 冻结 | 冻结 | 累加Weak次数 |
| `Peak <= 0.15` | Lost | 拒绝 | 冻结 | 冻结 | 累加Lost次数 |
| 连续Weak达到5帧 | 持续Weak | 拒绝 | 冻结 | 冻结 | 建议局部重捕获 |
| 连续Lost达到3帧 | Lost | 拒绝 | 冻结 | 冻结 | 建议局部重捕获 |

对应的流程树为：

```text
normalProposedRect + Peak + PSR
→ ConfidenceGuard::evaluate()
   ├─ positionAllowed = true
   │  ├─ 先接受位置候选
   │  ├─ scaleSearchAllowed决定是否继续测试尺度
   │  └─ modelUpdateAllowed决定是否累计模型更新帧数
   │
   └─ positionAllowed = false
      ├─ targetRect_保留previousRect
      ├─ 尺度和模型保持不变
      └─ recaptureSuggested决定是否尝试局部重捕获
```

将这些许可拆开，是因为每项错误操作产生的后果不同。短时Weak位置仍可能帮助框跟随目标，但Weak状态下修改尺度会改变下一帧搜索比例，更新模型会把不可靠区域写入长期状态。程序因此允许低风险的位置延续，同时先冻结尺度和学习；Weak持续过久后再停止沿弱响应漂移。

## 5 接受位置、重捕获与内部状态更新

候选位置被接受后，`normalProposedRect` 成为本帧的基础框。只有 `scaleSearchAllowed=true` 时，程序才围绕这个框构造一个放大或缩小候选，再计算一次FHOG响应。当前实现每帧只测试一个方向，并在相邻帧之间交替：

```text
本帧测试1.1倍放大
→ 下一帧测试1/1.1倍缩小
→ 再下一帧重新测试放大
```

尺度候选的Peak先乘 `0.95` 惩罚。惩罚后的分数超过原尺度Peak时，程序采用尺度候选框；否则继续使用原尺度框。选中的框经过尺寸和画面边界限制后写入 `targetRect_`，下一帧会以它为搜索中心。

Reliable还会打开模型更新许可。当前Demo16只累计连续允许更新的可靠帧，累计到5帧后执行一次训练：

```text
在已经接受的新targetRect_处重新提取FHOG
→ trainCorrelationFilter()生成本帧临时模型
→ interpolateTrackingModel()以0.005学习率融合历史模型
→ 更新完成后将可靠帧计数清零
```

训练时重新提取FHOG，是因为原尺度检测特征以旧框为中心，目标在其中已经发生偏移。新训练样本必须以本帧接受位置为中心，才能与“中心位置高响应”的训练标签对齐。

健康模板使用更严格的刷新条件：Peak高于0.60、PSR不低于7.0、连续满足5帧，并且距离上次刷新至少15帧。满足条件后，程序从当前 `targetRect_` 复制原图ROI，覆盖 `healthyTemplate_`。FHOG模型负责正常逐帧定位，健康模板留给低置信度后的独立恢复，两者的更新频率和使用方式不同。

候选位置被拒绝时，程序执行另一条路径：

```text
targetRect_ = previousRect
→ 不进行尺度搜索
→ 不训练FHOG模型
→ 不刷新健康模板
→ 达到连续Weak/Lost条件后，在lastReliableRect_附近进行模板匹配
```

`matchHealthyTemplateLocally()`使用健康模板在局部搜索区域中寻找最高的 `TM_CCOEFF_NORMED` 分数。分数达到当前阈值0.60后得到 `recoveredRect`。恢复框只给出了目标可能重新出现的位置，因此还要调用 `rebuildModel()`：在恢复位置重新提取FHOG、训练完整模型、更新内部框并清空置信度计数。重捕获失败时，旧框、旧模型和健康模板继续保留。

最终还要区分三种容易混淆的框：

```text
内部targetRect_
└─ 决定下一帧搜索区域，并参与可靠帧模型训练

最近训练图像区域modelImageTemplate_
└─ 只用于观察FHOG模型最近吸收了哪一块原图

外部displayRect
└─ 可以经过指数或Kalman平滑，只用于绘制或上层控制
```

外部平滑框不写回 `targetRect_`，因此不会改变搜索中心、FHOG缩放比例或模型训练区域。

## 6 万物跟踪完整流程的代码展示

下面代码是依据Demo05、Demo10至Demo16整理出的C++教学骨架。它用于展示调用顺序和决策关系，省略了空图检查、矩阵类型检查、异常处理、耗时统计和调试绘制。FHOG、相关滤波、尺度检测和模板匹配的算法内容继续由对应Demo函数实现。

当前工程的Demo16 `ProtectedFhogTracker` 已经包含大部分综合逻辑。这里使用 `CcSingleObjectTracker` 这个教学名称重新排列主路径，方便只看整体流程。代码中的 `extractTargetImage()`、`legalizeRect()`和`rebuildModel()`对应Demo16已有的私有辅助函数。

```cpp
/**
 * @brief 一帧万物跟踪的主要输出。
 *
 * targetRect是本帧结束后真正保存到跟踪器内部的框；
 * proposedRect是原尺度相关滤波提出的候选框，两者可能在Lost时不同。
 */
struct TrackingResult
{
    cv::Rect2f targetRect;   // 本帧结束后的内部框，下一帧会以它为搜索中心。
    cv::Rect2f proposedRect; // 原尺度检测提出的框；Lost时可能被拒绝。

    // normalPeak固定保存原尺度Peak，置信度和尺度比较都以它为基准。
    float normalPeak = 0.0F;

    // peak与psr保存最终采用的原尺度或尺度候选响应，供上层诊断显示。
    float peak = 0.0F;
    float psr = 0.0F;

    // 保存Reliable/Weak/Lost等级以及位置、尺度、模型和重捕获许可。
    confidence_recapture_demo::ConfidenceDecision confidence;

    bool positionAccepted = false;        // proposedRect或恢复框是否进入内部状态。
    bool scaleChanged = false;            // 最终框是否采用了放大/缩小候选。
    bool modelUpdated = false;            // 历史FHOG模板和Alpha本帧是否发生插值。
    bool healthyTemplateRefreshed = false; // 独立恢复模板本帧是否被新ROI覆盖。
    bool recaptureAttempted = false;      // 是否真正调用了局部模板匹配。
    bool recaptured = false;              // 模板匹配成功且FHOG模型是否重建成功。

    cv::Mat response; // 保存本帧最终采用的响应图，供上层诊断显示。
};


/**
 * @brief 组合前面Demo公共函数的纯视觉单目标跟踪器。
 *
 * initialize()建立第一帧模型；update()处理后续每一帧。
 * 本类拥有全部跨帧状态，上层只负责提供图像并消费TrackingResult。
 */
class CcSingleObjectTracker
{
public:
    // 使用第一帧和用户框建立模型；成功后才能调用update()。
    bool initialize(const cv::Mat& firstFrame, const cv::Rect2f& initialRect);

    // 消费一张后续帧，更新跨帧状态并返回本帧位置和所有决策结果。
    TrackingResult update(const cv::Mat& frame);

    // 释放模型和图像模板并清空计数器，使对象恢复到未初始化状态。
    void reset();

private:
    // 把目标框限制到配置尺寸和画面范围，返回原图坐标矩形。
    cv::Rect2f legalizeRect(const cv::Rect2f& rect) const;

    // 从原图目标框复制BGR/灰度ROI，供健康模板或调试图使用。
    cv::Mat extractTargetImage(
        const cv::Mat& frame,
        const cv::Rect2f& rect) const;

    // 在指定位置重新提取FHOG并训练完整模型；重捕获成功时调用。
    bool rebuildModel(
        const cv::Mat& frame,
        const cv::Rect2f& rect,
        bool refreshHealthyTemplate);

    // config_集中保存FHOG、相关滤波、尺度、学习率和重捕获参数。
    confidence_recapture_demo::ProtectedTrackerConfig config_;

    // featureExtractor_把原图目标框转换为固定24×24×31 FHOG特征。
    cc_fhog_demo::CcFhogExtractor featureExtractor_;

    // confidenceGuard_拥有连续Weak/Lost计数，并输出本帧各项操作许可。
    confidence_recapture_demo::ConfidenceGuard confidenceGuard_;

    // model_保存跨帧使用的FHOG模板特征与Alpha频谱。
    filter_train_demo::CorrelationFilterModel model_;

    cv::Rect2f targetRect_;       // 下一帧搜索中心所依据的内部框。
    cv::Rect2f lastReliableRect_; // 局部重捕获的参考中心。
    cv::Size frameSize_; // 初始化帧尺寸；目标框合法化和后续帧一致性检查使用它。

    cv::Mat healthyTemplate_;    // 低频刷新的原图恢复模板。
    cv::Mat modelImageTemplate_; // 最近一次进入FHOG模型的原图区域，仅供诊断。

    int nextScaleDirection_ = 1;              // +1测试放大，-1测试缩小。
    int modelUpdateEligibleFrameCount_ = 0;   // 连续允许模型更新的帧数。
    int healthyTemplateStableCount_ = 0;      // 连续满足健康模板条件的帧数。
    int framesSinceHealthyRefresh_ = 0;       // 距离上次健康模板刷新的帧数。
};
```

初始化函数只负责建立初始状态。`trainCorrelationFilter()`返回的模型由跟踪器持有，第一帧目标ROI同时成为初始健康模板：

```cpp
/**
 * @brief 使用第一帧和用户框建立初始相关滤波模型。
 * @param firstFrame 第一帧原图，生命周期只需覆盖本次调用。
 * @param initialRect 用户在原图坐标中选择的目标框。
 * @return 初始化成功后返回true，后续帧即可调用update()。
 *
 * 教学骨架省略输入和异常检查；正式代码应继续使用Demo16的检查逻辑。
 */
bool CcSingleObjectTracker::initialize(
    const cv::Mat& firstFrame,
    const cv::Rect2f& initialRect)
{
    // 清除上一个目标留下的模型、矩形、模板和连续帧计数，避免状态串用。
    reset();

    // 记录原图尺寸，后续所有矩形限制和新帧尺寸检查都以它为准。
    frameSize_ = firstFrame.size();

    // 对用户框执行最小/最大尺寸和画面边界限制，得到可以提取特征的原图框。
    targetRect_ = legalizeRect(initialRect);

    // extractFromFrame()内部建立搜索区、缩放、提取31通道FHOG并乘Hann窗。
    const cc_fhog_demo::CcFhogResult initialFeature =
        featureExtractor_.extractFromFrame(firstFrame, targetRect_);

    // 使用引用读取底层相关滤波配置，避免复制整组几何和训练参数。
    const auto& trackerConfig = config_.scaleTrackerConfig.trackerConfig;

    // 使用第一帧FHOG、高斯标签和高斯核相关训练模板特征与Alpha。
    model_ = filter_train_demo::trainCorrelationFilter(
        initialFeature.feature,
        trackerConfig.labelSigma,
        trackerConfig.kernelSigma,
        trackerConfig.regularization);

    // 初始化时用户框被视为可靠位置，也是局部重捕获的第一个参考中心。
    lastReliableRect_ = targetRect_;

    // extractTargetImage()返回独立ROI副本，视频帧释放或复用后模板仍然有效。
    healthyTemplate_ = extractTargetImage(firstFrame, targetRect_);

    // 初始模型吸收的图像区域与健康模板相同；clone()让两者独立持有数据。
    modelImageTemplate_ = healthyTemplate_.clone();

    // 新目标需要从干净状态重新累计尺度方向、置信度和更新间隔。
    confidenceGuard_.reset();
    nextScaleDirection_ = 1;
    modelUpdateEligibleFrameCount_ = 0;
    healthyTemplateStableCount_ = 0;
    framesSinceHealthyRefresh_ = 0;

    return true; // 所有初始状态已经建立，调用者可以开始逐帧调用update()。
}
```

下面的 `update()` 保留整个每帧主路径。为了让调用顺序连续可读，尺度候选的FHOG检测仍直接写在函数中，没有再包装成新的跟踪器。

```cpp
/**
 * @brief 处理一张后续视频帧并返回本帧跟踪结果。
 * @param frame 当前原始视频帧，尺寸应与初始化帧一致。
 * @return 最终内部框、置信度和本帧真正执行过的模块操作。
 *
 * 函数执行顺序固定为：原尺度检测→置信度判断→接受或恢复→模型维护→输出。
 */
TrackingResult CcSingleObjectTracker::update(const cv::Mat& frame)
{
    // result先保持默认false状态；只有实际执行的分支才把对应标志改为true。
    TrackingResult result;

    // previousRect在本帧开始后保持不变；Lost分支用它撤销不可靠候选位置。
    const cv::Rect2f previousRect = targetRect_;
    // trackerConfig提供FHOG几何、PSR排除半径和模型训练参数。
    const auto& trackerConfig = config_.scaleTrackerConfig.trackerConfig;

    // cellSize用于把响应图Cell位移转换成固定搜索图的像素位移。
    const int cellSize = trackerConfig.featureGeometry.cellSize;

    // 第一步：在上一帧内部框附近执行原尺度FHOG相关滤波检测。
    const cc_fhog_demo::CcFhogResult normalFeature =
        featureExtractor_.extractFromFrame(frame, previousRect);

    // detectTarget()使用历史model_输出原尺度响应、Peak、PSR和Cell位移。
    const response_detection_demo::DetectionResult normalDetection =
        response_detection_demo::detectTarget(
            model_,
            normalFeature.feature,
            trackerConfig.psrExclusionRadius);

    // 响应图中的Cell位移经过Cell大小和搜索图缩放比例恢复成原图像素位移。
    const cv::Point2f imageDisplacement =
        response_detection_demo::featureDisplacementToImage(
            normalDetection.peak.featureDisplacement,
            cv::Size(cellSize, cellSize),
            normalFeature.searchPatch);

    // 原尺度只修正中心位置，宽高先沿用previousRect。
    cv::Rect2f normalProposedRect(
        previousRect.x + imageDisplacement.x,
        previousRect.y + imageDisplacement.y,
        previousRect.width,
        previousRect.height);

    // 候选框越过画面时只移动位置，保持当前宽高不被边界截短。
    normalProposedRect =
        scale_tracker_demo::clampRectToFrame(normalProposedRect, frameSize_);

    // 先保存候选与原尺度诊断信息；置信度判断完成前不提交targetRect_。
    result.proposedRect = normalProposedRect;
    result.normalPeak = normalDetection.peak.peakValue;
    result.peak = normalDetection.peak.peakValue;
    result.psr = normalDetection.peak.psr;
    result.response = normalDetection.response.clone();

    // 第二步：Peak和PSR只产生操作许可，此时targetRect_仍是previousRect。
    result.confidence = confidenceGuard_.evaluate(
        result.normalPeak,
        normalDetection.peak.psr);

    // 模型更新必须来自连续可靠帧；一帧不许可就清空累计进度。
    if (!result.confidence.modelUpdateAllowed)
    {
        // 在线更新要求连续可靠；一帧Weak或Lost就从0重新累计。
        modelUpdateEligibleFrameCount_ = 0;
    }

    // 第三步A：候选位置被拒绝，保留旧状态并按条件尝试局部恢复。
    if (!result.confidence.positionAllowed)
    {
        // 拒绝本帧候选位置，使下一帧仍从上一帧内部框附近搜索。
        targetRect_ = previousRect;
        result.positionAccepted = false;

        // 只有功能开启、连续低分达到门槛且存在健康模板时，才执行恢复搜索。
        if (config_.enableRecapture &&
            result.confidence.recaptureSuggested &&
            !healthyTemplate_.empty())
        {
            // 进入该分支即记录上层已经发起一次局部恢复尝试。
            result.recaptureAttempted = true;

            // 在最后可靠框附近用独立健康模板计算归一化模板匹配响应。
            const confidence_recapture_demo::LocalRecaptureResult recapture =
                confidence_recapture_demo::matchHealthyTemplateLocally(
                    frame,
                    healthyTemplate_,
                    lastReliableRect_,
                    config_.recaptureConfig);

            if (recapture.success)
            {
                // 恢复框只给出候选位置；rebuildModel()还会重建FHOG和Alpha。
                // false表示暂不覆盖健康模板，避免一次误捕同时污染恢复依据。
                result.recaptured = rebuildModel(
                    frame,
                    recapture.recoveredRect,
                    false);

                if (result.recaptured)
                {
                    // 模型重建成功后，恢复框成为已接受位置和新的局部恢复参考中心。
                    result.positionAccepted = true;
                    lastReliableRect_ = targetRect_;
                }
            }
        }

        // 重捕获失败时targetRect_仍是previousRect；成功时rebuildModel()已写入恢复框。
        result.targetRect = targetRect_;
        return result; // 拒绝路径在这里结束，不再执行尺度、在线训练和模板刷新。
    }

    // 第三步B：位置获得许可，先把原尺度框作为默认选择。
    result.positionAccepted = true;
    cv::Rect2f selectedRect = normalProposedRect; // 默认采用原尺度位置结果。

    // 最终输出的Peak、PSR和响应图默认也来自原尺度检测；尺度胜出时会一起替换。
    response_detection_demo::DetectionResult selectedDetection = normalDetection;

    // 只有Reliable且PSR达标时才允许尺度与位置同时变化。
    if (config_.scaleTrackerConfig.enableScaleSearch &&
        result.confidence.scaleSearchAllowed)
    {
        // +1使用scaleStep测试放大，-1使用其倒数测试缩小。
        const float scaleFactor = nextScaleDirection_ > 0
            ? config_.scaleTrackerConfig.scaleStep
            : 1.0F / config_.scaleTrackerConfig.scaleStep;

        nextScaleDirection_ = -nextScaleDirection_; // 下一帧测试相反尺度方向。

        // 围绕原尺度候选中心同步缩放宽高，中心位置保持不变。
        cv::Rect2f scaleCandidateRect =
            scale_tracker_demo::scaleRectAroundCenter(
                normalProposedRect,
                scaleFactor);

        // 尺度候选先经过尺寸和画面边界限制，再参与特征提取。
        scaleCandidateRect = legalizeRect(scaleCandidateRect);

        // 候选框会建立自己的原图搜索区域，但输出仍是固定尺寸FHOG。
        const cc_fhog_demo::CcFhogResult scaleFeature =
            featureExtractor_.extractFromFrame(frame, scaleCandidateRect);

        // 使用同一历史模型检测尺度候选，使候选Peak可以与原尺度Peak比较。
        const response_detection_demo::DetectionResult scaleDetection =
            response_detection_demo::detectTarget(
                model_,
                scaleFeature.feature,
                trackerConfig.psrExclusionRadius);

        // scalePenalty给尺度切换增加成本，减少两个相邻尺度之间的高频抖动。
        const float penalizedScaleScore =
            scaleDetection.peak.peakValue *
            config_.scaleTrackerConfig.scalePenalty;

        // 惩罚后仍超过原尺度Peak时，尺度候选才获得最终选择权。
        if (penalizedScaleScore > result.normalPeak)
        {
            // 当前Demo真实实现还会把尺度响应的Cell位移换回原图并修正候选中心。
            // 这里用教学辅助函数表示这段已在Demo15验证过的坐标换算。
            selectedRect = makeScaleMeasuredRect( // 教学伪函数，工程中没有此公共接口。
                scaleCandidateRect,
                scaleDetection,
                scaleFeature.searchPatch,
                cellSize);

            // 伪函数输出仍需再次合法化，防止位移修正后越过画面边界。
            selectedRect = legalizeRect(selectedRect);

            // 框和诊断响应必须来自同一次检测，避免显示原尺度Peak却采用尺度框。
            selectedDetection = scaleDetection;
            result.scaleChanged = true;
        }
    }

    // 第四步：到这里才提交本帧接受的位置，下一帧会以它为搜索中心。
    targetRect_ = selectedRect;

    // 最终诊断结果跟随真正选中的响应；置信度仍保留原尺度判断结果。
    result.peak = selectedDetection.peak.peakValue;
    result.psr = selectedDetection.peak.psr;
    result.response = selectedDetection.response.clone();

    // 只有允许模型更新的可靠位置才替换重捕获中心；Weak位置不会改写它。
    if (result.confidence.modelUpdateAllowed)
    {
        lastReliableRect_ = targetRect_;
    }

    // 第五步：连续可靠帧到达间隔后，在新位置重新提取训练特征并更新模型。
    if (config_.enableOnlineUpdate &&
        result.confidence.modelUpdateAllowed &&
        config_.learningRate > 0.0F)
    {
        // 只累计连续满足模型更新许可的帧，计数在Weak/Lost时已经清零。
        ++modelUpdateEligibleFrameCount_;

        // 达到配置间隔后才重新提取训练特征，降低计算量和污染速度。
        if (modelUpdateEligibleFrameCount_ >= config_.modelUpdateInterval)
        {
            // 检测特征以previousRect为中心；训练必须在已提交的新targetRect_重新提取。
            const cc_fhog_demo::CcFhogResult trainingFeature =
                featureExtractor_.extractFromFrame(frame, targetRect_);

            // 使用居中的当前FHOG重新训练本帧模板和Alpha，历史model_暂时保持不变。
            const filter_train_demo::CorrelationFilterModel currentModel =
                filter_train_demo::trainCorrelationFilter(
                    trainingFeature.feature,
                    trackerConfig.labelSigma,
                    trackerConfig.kernelSigma,
                    trackerConfig.regularization);

            // 按learningRate同时融合模板特征与Alpha频谱，保持模型两部分时间一致。
            online_update_demo::interpolateTrackingModel(
                model_,
                currentModel,
                config_.learningRate);

            // 保存最近进入FHOG模型的原图区域，仅用于调试观察训练样本。
            modelImageTemplate_ = extractTargetImage(frame, targetRect_);

            // 本轮训练已经完成，下一轮更新间隔从0重新累计。
            modelUpdateEligibleFrameCount_ = 0;
            result.modelUpdated = true; // 告知上层历史相关滤波模型本帧确实改变。
        }
    }

    // 第六步：健康模板使用独立的高置信度连续帧和刷新间隔。
    ++framesSinceHealthyRefresh_;

    // 健康模板候选必须同时得到ConfidenceGuard许可并满足专用PSR阈值。
    const bool healthyCandidate =
        result.confidence.healthyTemplateRefreshAllowed &&
        result.confidence.psrValue >= config_.healthyTemplatePsrThreshold;

    // 条件连续满足时加1；任一帧失败便清零，防止跨过遮挡累计。
    healthyTemplateStableCount_ =
        healthyCandidate ? healthyTemplateStableCount_ + 1 : 0;

    // stableLongEnough控制可靠连续性，intervalPassed控制两次刷新最小间隔。
    const bool stableLongEnough =
        healthyTemplateStableCount_ >= config_.healthyTemplateStableFrames;

    const bool intervalPassed =
        framesSinceHealthyRefresh_ >= config_.healthyTemplateRefreshInterval;

    // 两个条件同时成立才覆盖独立恢复模板。
    if (stableLongEnough && intervalPassed)
    {
        // extractTargetImage()复制当前目标ROI，模板不依赖视频帧后续内存复用。
        healthyTemplate_ = extractTargetImage(frame, targetRect_);

        // 本次高置信度位置同时成为以后局部重捕获的搜索中心。
        lastReliableRect_ = targetRect_;

        // 刷新完成后清空两类计数，下一次必须重新满足完整条件。
        healthyTemplateStableCount_ = 0;
        framesSinceHealthyRefresh_ = 0;
        result.healthyTemplateRefreshed = true;
    }

    // 返回前写入最终内部框；下一次update()也会从同一个targetRect_继续。
    result.targetRect = targetRect_;
    return result;
}
```

`makeScaleMeasuredRect()` 在代码中明确标成教学伪函数。它代表Demo15和Demo16中已经存在的四步操作：读取尺度响应的 `featureDisplacement`、调用 `featureDisplacementToImage()`、把位移加到尺度候选框、调用 `legalizeRect()`。把这几步压缩后，`update()`的主判断关系更容易直接看出来。

上层视频循环只负责初始化、送帧和显示：

```cpp
// 打开视频文件；capture负责解码并按时间顺序提供视频帧。
cv::VideoCapture capture(videoPath);

cv::Mat frame;
// 先单独读取第一帧，因为初始化模型和用户选框都需要一张静止图像。
capture.read(frame);

// 用户只在第一帧选择一次任意目标；后续帧全部由跟踪器输出位置。
const cv::Rect initialRect = cv::selectROI("Select target", frame);

// 跟踪器对象持有FHOG模型、内部框、健康模板和所有连续帧计数。
CcSingleObjectTracker tracker;

// 用第一帧和用户框训练初始模型，后续循环不再重新读取用户框。
tracker.initialize(frame, cv::Rect2f(initialRect));

// capture.read()成功时frame已经更新为下一帧；读到结尾后循环自动停止。
while (capture.read(frame))
{
    // update()完成本帧检测、置信度决策、尺度选择和满足条件时的模型维护。
    const TrackingResult result = tracker.update(frame);

    // 如需外部平滑，只处理result.targetRect的显示副本，不回写tracker。
    // smoothForDisplay()和drawTrackingBox()都是上层教学伪函数，
    // 分别表示“只平滑显示副本”和“把浮点框绘制到画面”，不会修改tracker内部状态。
    const cv::Rect2f displayRect = smoothForDisplay(result.targetRect);
    drawTrackingBox(frame, displayRect);

    // 显示的是绘制后的当前帧；显示副本不会反向影响跟踪器内部状态。
    cv::imshow("Tracking", frame);

    // waitKey(1)既让OpenCV窗口处理消息，也允许用户按ESC主动退出。
    if (cv::waitKey(1) == 27)
    {
        break;
    }
}
```

从上层看，每帧只调用一次 `update()`；原尺度检测、置信度判断、尺度搜索、模型更新和重捕获全部由跟踪器内部按条件执行。这样上层业务不会绕过置信度保护直接修改模型，也不会把经过平滑的显示框错误写回下一帧搜索状态。
